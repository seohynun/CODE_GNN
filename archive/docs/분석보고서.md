## 1. 프로젝트 개요

### 1.1 문제 정의

온라인 리뷰 플랫폼에서의 **사기 리뷰(Fraudulent Review)** 는 단순히 한 명의 악의적인 작성자가 쓰는 경우보다, **여러 사람이 조직적으로 협력하여 집중적으로 작성하는 형태**로 나타나는 경우가 훨씬 많습니다. 이를 개별 리뷰 텍스트만으로 탐지하려는 기존 NLP 접근법은 아래와 같은 근본적인 한계를 가집니다.

- 개별 리뷰 하나만 보면 문법적으로 자연스럽고 내용도 그럴듯하게 작성되어 있어 텍스트만으로 판별하기 어려움
- 위장(camouflage) 리뷰: 사기 리뷰어들이 탐지를 피하기 위해 정상 리뷰도 함께 작성하는 경우가 빈번함
- 조직적 패턴은 **리뷰어들 사이의 관계(누가 누구와 같이 움직였는가)** 에서 드러나는데, 이는 NLP로는 포착 불가능

따라서 본 프로젝트는 **그래프 신경망(GNN)** 을 이용해 리뷰 노드 간의 구조적 관계를 모델링함으로써, 개별 리뷰로는 탐지가 어려운 **조직적 사기 네트워크를 그래프 구조에서 식별**하는 것을 목표로 합니다.

### 1.2 핵심 설계 원칙

| 원칙 | 내용 |
|------|------|
| **노드 단위** | 리뷰(Review) 노드로 고정 — 분류 대상은 리뷰 |
| **관계 설계** | 기본 관계(R-U-R, R-S-R) + 창의적 커스텀 관계(R-P-R, R-Sim-R) |
| **샘플링** | 단순 랜덤 금지 → 밀도 중심 샘플링 (그래프 연결성 보존) |
| **데이터 분할** | 샘플링 완료 후 유저 단위 분할 (R-U-R 라벨 누수 차단) |
| **평가** | PR-AUC (클래스 불균형 고려), Macro F1 |

## 2. 데이터 전처리 및 샘플링

> **관련 노트북**: `01_Data_Preprocessing.ipynb`

### 2.1 원본 데이터 현황

YelpZip 데이터셋의 원본 상태는 다음과 같습니다.

| 항목 | 값 |
|------|-----|
| 전체 리뷰 수 | 608,458건 |
| 사기 리뷰(원본 라벨 -1) | 80,439건 |
| 정상 리뷰(원본 라벨 +1) | 528,019건 |
| 사기 비율 | 13.2% |

**라벨 변환**: 원본의 `-1`(사기)/`+1`(정상) 표기를 프로젝트 규칙에 따라 `1`(사기)/`0`(정상)으로 변환했습니다.

### 2.2 밀도 중심 샘플링 (Density-Centric Sampling)

단순 랜덤 샘플링은 그래프 연결성을 파괴하기 때문에 **금지**되어 있습니다. 대신 아래의 4단계 전략으로 GNN 학습에 적합한 밀도 높은 서브그래프를 추출했습니다.

**Step 0. 시간 필터링**
- 데이터가 가장 집중된 **2013~2014년** 기간으로 한정
- 패턴의 일관성을 확보하고 노이즈 제거

**Step 1. 공간적 집중 (상위 200개 식당)**
- 리뷰 수 기준 상위 200개 식당으로 한정
- 데이터 밀도를 높여 GNN이 학습할 수 있는 충분한 엣지 형성

**Step 2. 사기 유저 전수 수집**
- 사기 리뷰를 단 한 번이라도 작성한 유저를 식별
- 해당 유저가 작성한 **모든 리뷰(정상 + 사기)** 를 포함
- 이유: 사기 리뷰어들은 탐지 회피를 위해 정상적인 위장 리뷰도 함께 작성함. 이 패턴 자체가 중요한 학습 신호

**Step 3. 활성 정상 유저 수집**
- 3개 이상의 리뷰를 작성한 활성 유저(Active User)만 수집
- 리뷰가 1~2개인 유저는 그래프 연결성 기여가 낮아 제외

**최종 샘플링 결과**

| 항목 | 값 |
|------|-----|
| 총 리뷰 수 | **50,950건** |
| 사기 리뷰 | 12,659건 (24.8%) |
| 정상 리뷰 | 38,291건 (75.2%) |
| 유저 수 | 17,439명 |
| 식당 수 | 200개 |
| 분석 기간 | 2013-01-01 ~ 2014-12-31 |

> 주목할 점: 원본 데이터의 사기 비율은 13.2%이지만, 샘플링 후 24.8%로 높아졌습니다. 이는 사기 유저를 전수 수집하고, 단발성 정상 유저를 제외했기 때문입니다. 이 밀도 높은 서브그래프가 GNN의 학습 효율을 크게 높였습니다.

## 3. 탐색적 데이터 분석 (EDA)

### 3-1. 버스트 패턴 분석

> **관련 노트북**: `02_EDA_Burst.ipynb`

#### 3-1-1. 분석 배경

사기 리뷰 네트워크의 가장 두드러진 특성 중 하나는 **단기간에 집중적으로 리뷰를 작성하는 "버스트(Burst)" 패턴**입니다. 개인 블로거나 실제 고객이 리뷰를 작성하는 패턴과 달리, 조직적 사기 리뷰어들은 캠페인 단위로 움직이기 때문에 특정 시간대에 폭발적으로 리뷰가 몰립니다.

#### 3-1-2. 데이터 분할 전략 (시간 기반 Cutoff)

버스트 피처를 train 데이터에서만 계산하여 데이터 누수를 방지했습니다.

- **기준일 탐색**: train/test 간 사기 비율 차이가 최소가 되는 시점을 탐색
- **최종 기준일**: `2014-06-27` (사기 비율 차이 0.0506)
- Train: 28,266건 (사기 비율 24.0%)
- Test: 13,613건 (사기 비율 29.0%)

#### 3-1-3. 버스트 패턴 분석 결과

세 가지 관점에서 버스트 패턴을 분석했습니다.

**① 매크로 버스트 (전체 시간축)**
- 전체 리뷰 48,946건 중 사기 리뷰 12,430건(25.4%) 발생
- 사기 리뷰어 수: 9,942명
- 사기 리뷰어가 작성한 전체 리뷰(정상+사기 합산): 13,042건
- 버스트 집중 월(월별 리뷰 급증 구간): **3개월** 식별

**② 마이크로 버스트 (개인 수준)**
- 사기 리뷰어의 **7일 이내 최대 리뷰 수(`burst_max7d`)** 가 정상 유저보다 현저히 높음
- 사기 리뷰어의 **버스트 비율(`burst_ratio`)**: 단기 집중 작성이 전체 활동의 큰 비중 차지

**③ 협력 버스트 (그룹 수준)**
- 특정 시점에 여러 사기 리뷰어가 동시에 동일 식당에 집중하는 패턴 발견
- 이는 캠페인 단위의 **조직적 어뷰징**을 강력히 시사

#### 3-1-4. GNN 피처화

분석 결과를 `burst_features.csv`로 저장하여 PC-GNN의 노드 피처로 활용했습니다.

| 피처명 | 설명 |
|--------|------|
| `user_burst_max7d` | 유저의 7일 이내 최대 리뷰 작성 수 |
| `user_burst_ratio` | 전체 리뷰 중 버스트 구간 리뷰의 비율 |

### 3-2. 별점 기반 사기 패턴 분석

> **관련 노트북**: `03_2_Rating_Fraud_Analysis.ipynb`

#### 3-2-1. 별점과 사기 비율의 관계

별점을 범주별로 분석한 결과, 사기 리뷰는 **극단적 별점(1점 또는 5점)에 집중**되는 명확한 패턴이 발견됐습니다.

| 별점 | 전체 리뷰 수 | 사기 리뷰 수 | 사기 비율 |
|------|------------|------------|---------|
| 1점 | 1,922건 | 1,192건 | **62.0%** |
| 2점 | 2,896건 | 805건 | 27.8% |
| 3점 | (중간) | - | 낮음 |
| 4점 | (중간) | - | 낮음 |
| 5점 | 다수 | 다수 | 높음 |

- **1점(Pollute 전략)**: 경쟁 업체의 평점을 낮추기 위한 별점 테러 — 62%가 사기
- **5점(Push 전략)**: 자사 식당의 평점을 끌어올리기 위한 조작 — 5점대에서도 사기 비율 높음

#### 3-2-2. 파생 피처 설계

EDA 결과를 바탕으로 아래의 피처들을 설계하고 `features_rating.csv`로 저장했습니다.

| 피처명 | 설명 | 사기 탐지 근거 |
|--------|------|--------------|
| `rating_deviation` | 리뷰 별점 − 해당 식당 평균 별점 | 사기 리뷰일수록 이탈도 큼 |
| `norm_rating_entropy` | 유저의 별점 부여 패턴 다양성 (정규화) | 사기 유저는 특정 별점만 집중 부여 |
| `is_cold_start` | 새 유저 또는 새 식당 여부 플래그 | 신뢰 정보 부족 구간 표시 |
| `is_single_review` | 해당 식당에 리뷰가 단 1건인 유저 플래그 | 일회성 사기 계정 특성 반영 |

> 핵심 발견: `rating_deviation`은 사기 탐지에서 매우 강력한 신호였습니다. 이 수치가 높은 리뷰일수록 R-P-R(동일 식당 내 유사 의심도 리뷰 연결) 엣지 구성의 우선순위에 사용했습니다.

### 3-3. 텍스트 네트워크 분석 및 커스텀 엣지 구축

> **관련 노트북**: `03_1_Text_Network_Analysis.ipynb`

#### 3-3-1. 분석 배경 및 목적

기존 GNN 모델에서는 주로 메타데이터(유저 ID, 식당 ID, 별점, 날짜) 기반의 관계만을 그래프 엣지로 사용해왔습니다. 하지만 사기 리뷰 캠페인에서는 종종 **동일한 템플릿 문구를 여러 계정이 나눠 작성**하거나, 매우 유사한 표현을 반복하는 패턴이 나타납니다. 이 신호를 포착하기 위해 **텍스트 유사도 기반 커스텀 엣지(R-Sim-R)** 를 설계했습니다.

#### 3-3-2. PMI 단어 네트워크 분석

먼저 사기/정상 리뷰에서 각각 변별력 있는 어휘를 식별했습니다.

- train 기반으로 TF-IDF 어휘 2,826개 풀 구성
- PMI(점별 상호정보량) 네트워크 구축: 노드 526개, 엣지 117,551개
- 사기 리뷰 특성 어휘와 정상 리뷰 특성 어휘를 분리 → 4개의 단어 커뮤니티 탐지
- **변별력 상위 300개 어휘**를 커스텀 엣지 구성에 활용

#### 3-3-3. 텍스트 유사도 기반 커스텀 엣지 (R-Sim-R)

300개 변별 어휘로 TF-IDF 행렬(50,950 × 300)을 구성하고, 청크 단위(2,000개씩) 코사인 유사도를 전체 리뷰 쌍에 대해 계산했습니다.

- 계산 방식: 청크 코사인 유사도 (50,950 × 50,950 전체 커버)
- 임계값: 코사인 유사도 **≥ 0.70**
- **최종 엣지 수: 319,670개**

이 엣지는 메타데이터만으로는 포착할 수 없는 **"같은 방식으로 쓰인 리뷰들의 연결"** 을 표현하며, PC-GNN의 가장 중요한 커스텀 관계(R-Sim-R)로 활용됩니다.

## 4. GNN 모델 설계 및 시행착오

### 4-1. 1차 시도: SixRelCAREGNN

> **관련 노트북**: `05_Model_Training.ipynb`

#### 4-1-1. 설계 개요

처음에는 **6종의 관계(Relation)와 CARE 유사도 게이트를 결합한 SixRelCAREGNN**을 설계했습니다.

| 항목 | 내용 |
|------|------|
| 엣지 종류 | R-U-R, R-T-R, R-S-R, R-P-R, R-B-R, R-Sim-R (6종) |
| 피처 차원 | 101차원 (EDA 행동피처 37개 + TF-IDF SVD 64차원) |
| 핵심 아이디어 | CARE 유사도 게이트로 위장 이웃의 영향 억제 |
| 데이터 분할 | 시간 기반 cutoff (2014-06-28 기준) |

**베이스라인**: R-S-R 단일 엣지 + rating+TF-IDF 65차원의 기본 GCN

#### 4-1-2. 결과

| 모델 | PR-AUC | Macro F1 |
|------|--------|----------|
| BaselineGCN | 0.4899 | 0.6379 |
| SixRelCAREGNN | 0.5595 | 0.7009 |
| **개선폭** | **+14.2%** | **+9.9%** |

**Relation Attention 분석**: R-U-R(동일 유저) 관계가 0.582로 압도적으로 높은 기여를 보였으며, 이는 "같은 유저가 쓴 리뷰들끼리 사기 신호를 강하게 공유"함을 뜻합니다.

#### 4-1-3. 문제점 및 한계

성능 수치 자체는 유효했으나 몇 가지 아쉬운 점이 있었습니다.

- PR-AUC 0.56은 클래스 불균형 기준(랜덤 = 0.13)으로는 충분히 의미 있지만, 절대 수치로 보면 낮아 보임
- 시간 기반 분할이라 train/test 간 분포 차이가 커 성능이 제한될 수 있음
- 보다 강력한 배치 샘플링 전략(불균형 대응)이 필요하다는 판단

### 4-2. 2차 시도: RGCN 베이스라인 — 라벨 누수 문제 발견 및 해결

> **관련 노트북**: `05_1_PCGNN.ipynb` (초기 단계)

#### 4-2-1. 초기 설계

두 번째 실험에서는 PC-GNN과 비교할 강력한 베이스라인을 설계하려 했습니다. R-U-R(동일 유저) 엣지를 전체 그래프에 사용한 단순 RGCN을 베이스라인으로 설정했습니다.

#### 4-2-2. 문제 발생: 베이스라인이 0.8011로 너무 높음

첫 실행 결과, RGCN 베이스라인이 **val PR-AUC 0.8011**이라는 비현실적으로 높은 성능을 보였습니다.

```
✅ RGCN 최종: PR-AUC=0.8011  Macro F1=0.8774
```

**문제 분석**: 이는 **구조적 라벨 누수(Structural Label Leakage)** 때문이었습니다.

- YelpZip 데이터셋의 특성상, 사기 리뷰어의 모든 리뷰는 (정상처럼 보여도) 거의 대부분 사기 라벨을 가집니다
- 즉, 같은 유저가 쓴 리뷰들은 라벨이 동일할 가능성이 매우 높습니다
- R-U-R 엣지를 전체 그래프에 포함하면, GNN이 val/test 노드들을 train 노드와 R-U-R 경로로 연결하여 라벨 정보를 전파받게 됩니다
- 결과적으로 GNN이 실제로 학습한 게 아니라 "같은 유저를 따라가면 라벨을 알 수 있다"는 손쉬운 지름길을 학습한 것

#### 4-2-3. 해결: 유저 단위 분할 + Train-only 엣지

두 가지 수정을 동시에 적용했습니다.

**① 유저 단위 분할(User-based Split)**
- 기존: 리뷰 단위 랜덤 분할 → 같은 유저의 리뷰가 train/val에 섞임
- 수정: 유저 단위로 먼저 분할한 뒤, 각 유저의 모든 리뷰를 같은 파티션에 배치
- 비율: Train 60% / Val 20% / Test 20% (유저 수 기준)

**② Train-only R-U-R 엣지 (베이스라인 전용)**
- 베이스라인 RGCN에서는 train 노드들 사이에서만 R-U-R 엣지 구성
- val/test 노드가 완전히 고립(isolated) → GNN이 rating_norm 1차원 피처만으로 판단해야 함
- 이것이 "그래프 없는 수준의 진정한 기준선"

#### 4-2-4. 수정 후 결과

```
✅ RGCN 최종: PR-AUC=0.2739  Macro F1=0.1956
```

이 수치가 바로 **피처도 없고, 그래프 구조도 최소화된 진정한 기준선(True Baseline)** 입니다. 이를 기점으로 PC-GNN의 개선을 공정하게 측정할 수 있게 됐습니다.

---

### 4-3. 최종 모델: PC-GNN

#### 4-3-1. 설계 철학

PC-GNN은 **"Picker(피커)"와 "Chooser(추저)"** 라는 두 가지 핵심 메커니즘을 결합한 모델입니다.

- **Picker**: 극심한 클래스 불균형을 배치 레벨에서 해결하는 동적 샘플러. 사기 리뷰 전량 + 정상 리뷰 3배를 매 에포크마다 샘플링하여 배치 내 사기 비율을 25%로 맞춤
- **Chooser**: 각 리뷰 노드가 이웃 노드의 메시지를 받을 때, 어텐션 기반으로 "믿을 만한 이웃"과 "위장 이웃"을 구분하여 선택적으로 집계 (ChooserConv)

#### 4-3-2. 그래프 구성 (4종 관계)

| 관계 | 설명 | 엣지 수 | 설계 근거 |
|------|------|--------|----------|
| **R-U-R** | 동일 유저가 쓴 리뷰 연결 | 254,784개 | 사기 리뷰어의 모든 리뷰는 패턴 공유 |
| **R-S-R** | 동일 식당 + 동일 별점 리뷰 연결 | 481,794개 | 별점 조작 캠페인은 같은 별점으로 몰림 |
| **R-P-R** | 동일 식당 내 의심도 높은 리뷰 연결 | 724,080개 | `rpr_suspicion` 점수 기반 우선 연결 |
| **R-Sim-R** | 텍스트 코사인 유사도 ≥ 0.70 리뷰 연결 | 319,670개 | 사기 캠페인의 템플릿 문구 패턴 포착 |

> R-U-R은 `max_per_node=10` 제한을 적용하여 heavy user(수십~수백 개의 리뷰를 가진 유저)로 인한 엣지 폭발 문제를 방지했습니다.

#### 4-3-3. 피처 설계 (72차원)

| 구분 | 피처 | 차원 |
|------|------|------|
| 행동 피처 | `rating`, `user_review_count`, `user_avg_rating`, `user_rating_std`, `activity_span`, `user_burst_max7d`, `is_cold_start`, `is_single_review` | 8차원 |
| 텍스트 피처 | TF-IDF + TruncatedSVD | 64차원 |
| **합계** | | **72차원** |

행동 피처는 train 데이터만으로 계산(누수 방지), StandardScaler로 정규화했습니다.

#### 4-3-4. 학습 전략

| 항목 | 설정값 | 이유 |
|------|--------|------|
| Picker ratio | 정상:사기 = 3:1 | 클래스 불균형 대응 |
| FocalLoss γ | 2.0 | 어려운 샘플에 집중 |
| 클래스 가중치 | 사기 클래스 ×1.5 추가 | 사기 리뷰 재현율 강화 |
| hidden_dim | 64 | CPU 학습 속도 최적화 (128→64, 어텐션 연산 4× 감소) |
| Optimizer | AdamW (lr=5e-4, wd=5e-4) | 과적합 방지 |
| 스케줄러 | CosineAnnealingLR | 학습 후반 안정적 수렴 |
| 에포크 | 최대 60 (Early Stopping patience=10) | 효율적 학습 종료 |

#### 4-3-5. 학습 과정

```
[E 10] val PR-AUC=0.5761   F1=0.2065  (52초)
[E 20] val PR-AUC=0.7703   F1=0.2160  (101초)
[E 30] val PR-AUC=0.8458   F1=0.7448  (146초)
[E 40] val PR-AUC=0.8578   F1=0.7589  (192초)
[E 50] val PR-AUC=0.8609   F1=0.7607  (242초)
[E 60] val PR-AUC=0.8614   F1=0.7610  (295초)
```

에포크 20~30 사이에서 F1이 급격히 향상(0.22 → 0.74)됐는데, 이는 모델이 단순히 "모두 정상"으로 예측하는 전략에서 벗어나 실제로 사기 클래스를 구분하기 시작한 시점을 보여줍니다.

#### 4-3-6. 속도 최적화 과정 (시행착오)

초기 PC-GNN 학습 시도에서 CPU 환경의 과도한 연산 부담으로 **KeyboardInterrupt가 발생**했습니다. 원인은 다음과 같았습니다.

- `hidden_dim=128`로 ChooserConv의 어텐션 연산이 과중: 각 엣지마다 Linear(256→1) 연산 수행
- R-U-R 엣지에 `max_per_node` 제한이 없어 heavy user로 인한 엣지 수 폭발

이를 해결하기 위해 아래 세 가지를 수정했습니다.

| 수정 항목 | 변경 전 | 변경 후 | 효과 |
|----------|---------|---------|------|
| `hidden_dim` | 128 | 64 | 어텐션 연산 4× 감소 |
| R-U-R `max_per_node` | 무제한 | 10 | 엣지 수 상한 적용 |
| `epochs` | 80 | 60 (+ Early Stopping) | 총 학습 시간 단축 |

수정 후 약 5분(295초) 만에 학습이 완료됐습니다.

## 6. 본선 고도화 계획

예선에서는 리뷰(Review) 노드 간의 동형(Homogeneous) 그래프를 구축했습니다. 본선에서는 이를 근본적으로 확장하여 **이기종 정보 네트워크(Heterogeneous Information Network, HIN)** 구조로 고도화할 계획입니다.

### 6.1 아키텍처 전환: Homogeneous → HGNN + PC-GNN 철학

대회 가이드라인에서 "분류 대상 노드만 리뷰 노드면 되고, Product·Date 등을 보조 노드로 설정하는 것은 가능하다"는 점을 확인했습니다. 이를 바탕으로 아래 전략을 채택합니다.

**기본 구조: HGNN (Heterogeneous GNN)**
```
리뷰(Review) ──writes──▶ 유저(User) ──written_by──▶ 리뷰
리뷰(Review) ──about───▶ 식당(Product) ──has───────▶ 리뷰
리뷰(Review) ──at─────▶ 시간창(TimeWindow) ──contains──▶ 리뷰
```

**결합 전략: PC-GNN의 Pick & Choose 철학 유지**
- **Picker**: 리뷰 노드에만 적용 (사기 리뷰 전량 + 정상 N배 배치)
- **Chooser**: 각 관계 유형(엣지 타입)별로 어텐션 기반 이웃 선별 적용

이 구조의 핵심 장점은 현재 O(k²)로 폭발하는 R-U-R 엣지 문제를 O(k)로 해결한다는 점입니다. 예: 20개 리뷰를 가진 유저의 경우 현재 190개 R-U-R 페어 → HGNN에서는 유저 노드 1개만 연결 (20개 엣지).

### 6.2 현행 아키텍처의 한계점

예선 모델에서는 신속한 프로토타이핑을 위해 식당(Product) 노드의 피처를 **6차원의 리뷰 파생 통계치**(`prod_avg_rating`, `prod_fraud_ratio` 등)로만 구성했습니다. 이는 식당 자체의 고유한 특성(Domain Context)이 배제된 상태로, 모델이 "왜 하필 이 식당에 사기 리뷰가 몰렸는가?"라는 외부적 동기를 파악하는 데 한계가 있습니다.

---

### 6.3 핵심 고도화 목표 1: 식당 노드 메타데이터 임베딩

단순 통계치를 넘어, 식당 자체의 프로필 데이터를 EDA 및 피처 엔지니어링하여 식당 노드의 차원을 대폭 확장합니다. 현재 GNN 파이프라인의 피처 배열에 차원만 추가하면 즉각적으로 모델에 반영되는 **확장 가능한(Scalable) 구조**가 이미 완성되어 있습니다.

**💡 Action Item 1: 카테고리 피처**
- 'Italian', 'Fast Food', 'Local Pub' 등 카테고리별로 발생하는 사기 패턴(예: 관광지 맛집 위주의 평점 조작)을 모델이 학습하도록 One-hot 인코딩 또는 임베딩 처리

**💡 Action Item 2: 지리적 피처**
- 우편번호 기반 지역 클러스터링으로 특정 지역 상권 전체를 타겟으로 하는 조직적 사기 봇넷(Botnet) 공격망 탐지

**💡 Action Item 3: 영업 기간 및 가격대**
- 개업 직후 평점을 끌어올리기 위한 '초기 부스팅(Cold-start Boosting)' 패턴 포착

---

### 6.4 핵심 고도화 목표 2: 외부 환경 데이터 크롤링 및 융합

현재 모델은 Yelp 내부 데이터에만 의존합니다. 내부 데이터만으로는 사기 리뷰가 **'왜 하필 그 시점에, 그 식당에'** 집중됐는지의 현실 세계 동기를 설명하기 어렵습니다. 본선에서는 웹 크롤링 및 외부 API를 활용하여 **현실 세계 환경 변수(Contextual Data)** 를 수집하고 피처로 결합할 계획입니다.

**💡 Action Item 1: 휴업·폐업 정보 및 운영 이력 크롤링**

사기꾼들의 흔한 패턴 중 하나는 영업하지 않는 기간(임시 휴업, 리모델링, 개업 전)에 평점 조작 작업을 몰아서 수행하는 것입니다.

- **수집 데이터**: Google Maps, Tripadvisor 등 또는 웹 아카이브를 크롤링하여 **가게의 실제 영업 상태 변경 이력** 수집
- **적용 방안**: 리뷰 작성 일자와 해당 가게의 실제 영업 상태를 대조하는 파생 변수(`is_review_during_closed`) 생성. 영업 중단 기간에 작성된 리뷰에 페널티 가중치 부여

**💡 Action Item 2: 지역별 시즌 및 이벤트 캘린더 연동**

관광지 상권의 경우, 특정 시즌(여름휴가, 대형 축제 등)을 앞두고 검색 상위 노출을 위해 대규모 리뷰 조작이 발생합니다.

- **수집 데이터**: 지역별 관광 성수기, 대형 축제 일정, 휴일 정보 크롤링
- **적용 방안**: '성수기 진입 D-30일 전'과 같은 이벤트 근접성 피처(`days_until_peak_season`)를 식당 노드에 추가. 특정 시기의 리뷰 버스트가 정상인지 사기인지 변별

**💡 Action Item 3: 경쟁 상권 밀집도 및 트렌드 데이터 수집**

경쟁이 치열한 상권일수록 자가 발전(어뷰징) 또는 경쟁사 별점 테러 확률이 높습니다.

- **수집 데이터**: 특정 지역(ZIP Code) 내 동종 카테고리 식당의 폐업률, 신규 오픈 비율, 상권 트렌드 지수 크롤링
- **적용 방안**: 식당 노드의 피처로 상권 밀집도 및 경쟁 강도 변수를 추가하여, 모델이 주변 경쟁 환경까지 고려하도록 유도

### 6.5 핵심 고도화 목표 3: 다중 관계망 고도화

식당 노드의 정보가 풍부해짐에 따라, 기존의 단순한 `리뷰-식당(R-P-R)` 연결을 넘어선 새로운 그래프 연결망을 구축합니다.

**💡 새로운 엣지 유형 제안**

| 엣지 | 의미 | 포착 패턴 |
|------|------|----------|
| `Restaurant-[SimilarCategory]-Restaurant` | 동일 상권 경쟁 업체 간 연결 | 경쟁사 별점 테러 패턴 |
| `User-[VisitsSimilar]-Restaurant` | 멀리 떨어진 동종 식당들만 순회하는 유저 | 비정상적 방문 동선 추적 |

---

### 6.6 본선 개발 로드맵 요약

```
[현재] Homogeneous PC-GNN (리뷰 노드만)
   ↓
[Step 1] HeteroData 재구성
         Review + User + Product + TimeWindow 노드
         관계별 MessagePassing 분리
   ↓
[Step 2] 식당 메타데이터 피처 확장
         카테고리 임베딩 + 지리 클러스터 + 영업 기간
   ↓
[Step 3] 외부 데이터 크롤링 및 융합
         영업 이력 + 시즌 이벤트 + 상권 밀집도
   ↓
[Step 4] HGNN + PC-GNN (Chooser per relation type)
         관계 유형별 어텐션 선별 집계
         → 최종 HIN 기반 완전 이기종 사기 탐지 모델
```

## 7. 모델 기반 인사이트 및 활용 방안

### 7.0 단계별 기여도 분해 실험 (어블레이션 분석)

단순히 "베이스라인 → 최종"의 통합 비교만으로는 성능 향상이 **피처 설계 덕분인지, 모델 구조 덕분인지** 알 수 없습니다. 이를 정확히 분리하기 위해 아래 3단계 실험을 설계했습니다.

#### 실험 설계

| 단계 | 모델 | 피처 | 엣지 | 학습 전략 |
|------|------|------|------|----------|
| **단계 1** (순수 베이스라인) | RGCN | rating_norm **1차원** | train-only R-U-R | CrossEntropy |
| **단계 2** (피처만 교체) | RGCN | EDA 파생변수 **72차원** | train-only R-U-R (동일) | CrossEntropy (동일) |
| **단계 3** (모델 전체 교체) | PC-GNN | EDA 파생변수 **72차원** (동일) | 4종 전체 그래프 | Chooser+Picker+FocalLoss |

- **단계 1→2**: 모델·엣지·학습 전략을 그대로 유지하고 피처만 교체 → **피처 단독 기여도 측정**
- **단계 2→3**: 피처를 고정하고 모델·엣지·학습 전략 전체를 교체 → **모델 구조 단독 기여도 측정**

#### 실험 결과

| 단계 | 설명 | PR-AUC | Macro F1 |
|------|------|--------|----------|
| 단계 1 | RGCN + 1차원 피처 | 0.2739 | 0.1956 |
| 단계 2 | RGCN + 72차원 파생변수 | *(노트북 [14]셀 실행 후 기입)* | *(노트북 [14]셀 실행 후 기입)* |
| 단계 3 | PC-GNN + 72차원 파생변수 | 0.8674 | 0.7666 |

#### 구간별 개선폭 해석

**▲ 1→2 구간 (피처 교체 효과)**

- 베이스라인 RGCN의 구조와 엣지(train-only R-U-R)를 그대로 유지한 채 피처만 1차원 → 72차원으로 교체
- val/test 노드는 여전히 그래프에서 **완전히 고립** — 그래프 구조 정보 전혀 없음
- 이 구간의 PR-AUC 상승분은 **EDA에서 발굴한 행동 피처와 텍스트 임베딩의 독자적 판별력**을 의미
- 핵심 해석: `user_burst_max7d`(버스트 패턴), `rating_deviation`(별점 편차), `activity_span`(활동 기간) 등 8개 행동 피처가 그래프 없이도 이미 강력한 사기 신호를 보유하고 있음을 입증

**▲ 2→3 구간 (모델 교체 효과)**

- 피처를 72차원으로 고정한 채 RGCN → PC-GNN으로 전환 (4종 엣지 + Chooser 어텐션 + Picker + FocalLoss)
- 이 구간의 PR-AUC 추가 상승분은 **그래프 구조와 학습 전략이 만들어낸 순수 추가 기여**
- 핵심 해석: R-S-R·R-P-R·R-Sim-R 엣지로 val/test 노드가 비로소 그래프에 연결되어 **이웃의 사기 신호가 전파**되기 시작함. 피처만으로는 포착 불가능한 조직적 공모 패턴이 그래프 전파를 통해 드러남

#### 기여 비율 요약

| 지표 기준 | 피처 교체(1→2) 기여 | 모델 교체(2→3) 기여 |
|-----------|---------------------|---------------------|
| PR-AUC 개선분 | *(노트북 [15]셀 출력 참조)* % | *(노트북 [15]셀 출력 참조)* % |
| Macro F1 개선분 | *(노트북 [15]셀 출력 참조)* % | *(노트북 [15]셀 출력 참조)* % |

> **핵심 결론**: EDA를 통한 피처 설계(전처리 품질)와 GNN 구조 설계(모델 품질)는 **상호 보완적이며 동시에 필수적**입니다. 두 기여도 중 어느 하나만으로는 현재 성능에 도달 불가능하며, 양쪽이 함께 작동할 때 비로소 조직적 사기 패턴 탐지가 가능해집니다.

### 7.1 베이스라인 대비 개선 원인 분석

PC-GNN이 RGCN 베이스라인(PR-AUC 0.2739)보다 압도적으로 높은 성능(PR-AUC 0.8674)을 달성한 것은 단일 요인이 아니라, **다섯 가지 설계 결정이 복합적으로 작용한 결과**입니다.

---

#### ① 피처 차원의 대폭 확장: 1차원 → 72차원

베이스라인 RGCN은 `rating_norm` 단 1차원만 사용했습니다. 이는 GNN이 학습할 수 있는 정보 자체가 "별점이 높냐 낮냐" 하나뿐이라는 뜻입니다.

PC-GNN은 EDA를 통해 발굴한 **72차원의 풍부한 피처**를 제공합니다.

| 피처 그룹 | 핵심 신호 | 사기 탐지 기여 |
|----------|----------|--------------|
| `user_burst_max7d` | 7일 내 최대 리뷰 수 | 캠페인성 폭발 작성 포착 |
| `user_rating_std` | 유저의 별점 표준편차 | 사기 유저는 특정 별점에 편중 |
| `rating_deviation` | 식당 평균과의 별점 괴리 | 극단적 조작 별점 식별 |
| `is_cold_start` | 신규 유저/식당 여부 | 일회성 사기 계정 표시 |
| TF-IDF SVD 64차원 | 리뷰 텍스트 의미 | 템플릿 문구 패턴 내재화 |

**결론**: 피처가 풍부해질수록 GNN이 각 리뷰 노드를 더 입체적으로 표현할 수 있습니다. "누가, 어떻게, 어떤 내용으로 썼는가"를 동시에 인코딩한 것이 개선의 첫 번째 원인입니다.

---

#### ② 그래프 관계 다양화: 1종 엣지 → 4종 엣지

베이스라인 RGCN은 val/test 노드를 완전히 고립시킨 train-only R-U-R 1종만 사용했습니다. 이 구조에서는 GNN이 이웃으로부터 어떤 정보도 받지 못하므로, 사실상 피처만으로 분류하는 것과 다름없습니다.

PC-GNN은 **4종의 관계를 전체 그래프에 적용**하여 노드들이 서로 정보를 교환할 수 있도록 했습니다.

| 관계 | 포착하는 패턴 | Attention |
|------|-------------|-----------|
| R-U-R | 같은 유저의 모든 리뷰가 패턴을 공유 | **0.540** |
| R-Sim-R | 유사한 템플릿 문구로 쓰인 리뷰들 | 0.200 |
| R-P-R | 같은 식당 내 의심도 높은 리뷰들 | 0.143 |
| R-S-R | 같은 식당의 같은 별점 리뷰들 | 0.117 |

특히 **R-Sim-R(텍스트 유사도 기반 커스텀 엣지)이 Attention 2위(0.200)** 를 기록한 것은, EDA에서 설계한 커스텀 관계가 실제로 사기 탐지에 유효함을 모델 스스로 입증한 것입니다.

**결론**: 다양한 관계를 통해 사기 리뷰들이 서로 "사기 신호"를 전달하고 증폭시키는 그래프 전파(Graph Propagation)가 가능해졌습니다. 혼자서는 판별하기 어려운 위장 리뷰도, 같은 유저의 다른 사기 리뷰들과 연결됨으로써 탐지될 수 있습니다.

---

#### ③ Chooser 어텐션: 위장 이웃의 영향 차단

사기 리뷰어들은 탐지를 피하기 위해 **정상적인 리뷰도 함께 작성**합니다. 이 때문에 단순 평균 집계(RGCN 방식)를 쓰면, 사기 리뷰가 자신의 정상 위장 리뷰로부터 "나는 정상이다"라는 잘못된 신호를 받게 됩니다.

PC-GNN의 **ChooserConv**는 각 엣지마다 어텐션 가중치를 학습하여, 믿을 수 있는 이웃의 메시지는 강하게 전달하고 혼란을 주는 위장 이웃의 메시지는 약하게 처리합니다.

```
α_ij = sigmoid( W_attn · [h_i || h_j] )   # 이웃 j가 노드 i에게 보내는 신뢰도
메시지 = α_ij × h_j                        # 신뢰도만큼만 전달
```

**결론**: 기존 GNN이 "모든 이웃을 똑같이 믿는" 방식이었다면, PC-GNN은 "의심스러운 이웃은 걸러내는" 방식입니다. 이것이 위장 리뷰가 많은 YelpZip 데이터셋에서 특히 효과적이었던 이유입니다.

---

#### ④ Picker 배치 샘플링: 클래스 불균형 해소

데이터의 사기 비율은 24.8%입니다. 전체 train 데이터를 그대로 쓰면 모델은 "모두 정상"으로 예측하는 것만으로도 75%의 정확도를 얻을 수 있어, 사기 탐지 학습 신호가 묻혀버립니다.

PC-GNN의 **Picker**는 매 에포크마다 동적으로 배치를 구성합니다.
- 사기 리뷰: **전량 포함**
- 정상 리뷰: **3배만 샘플링**
- 결과 배치 내 사기 비율: **25%** (자연 비율보다 집중)

학습 과정을 보면, 에포크 20~30 사이에서 F1이 0.22 → 0.74로 급등하는 전환점이 나타납니다. 이것이 모델이 "모두 정상"이라는 손쉬운 전략을 포기하고 진짜 사기 패턴을 학습하기 시작한 시점입니다.

**결론**: Picker가 없었다면 모델은 사기 클래스를 제대로 학습하지 못해 Recall이 매우 낮았을 것입니다. 실제로 최종 사기 클래스 Recall이 0.84에 달하는 것은 Picker의 직접적인 기여입니다.

---

#### ⑤ Focal Loss: 경계 케이스(위장 리뷰)에 집중

CrossEntropyLoss는 모든 샘플에 동일한 학습 비중을 부여합니다. 그러나 위장 리뷰처럼 "쉽게 분류되는 샘플"에 과도한 학습 자원이 낭비되면, 진짜 어려운 경계 케이스 학습이 부족해집니다.

FocalLoss(γ=2.0)는 이미 잘 분류된 샘플의 손실을 자동으로 감쇄합니다.

```
FocalLoss = (1 - p_t)^γ × CrossEntropy
```

이미 확신이 높은 샘플(p_t → 1)은 (1-p_t)^2 → 0으로 손실이 거의 0이 되고, 불확실한 경계 케이스(p_t → 0.5)에 학습이 집중됩니다.

**결론**: Focal Loss가 위장 리뷰처럼 겉으로는 정상처럼 보이는 어려운 케이스에 집중 학습함으로써, 단순한 사기/정상 구분을 넘어 미묘한 위장 패턴까지 포착할 수 있게 됐습니다.

### 7.2 개선 요인 종합 정리

| 개선 요인 | 베이스라인 | PC-GNN | 기여 핵심 |
|----------|----------|--------|----------|
| 피처 | rating_norm 1차원 | EDA 피처 72차원 | 리뷰 노드의 표현력 대폭 향상 |
| 엣지 | train-only R-U-R | 4종 전체 그래프 | 그래프 전파로 집단 패턴 포착 |
| 집계 | 균등 평균 | Chooser 어텐션 | 위장 이웃의 혼란 신호 차단 |
| 배치 | 전체 train | Picker 동적 샘플링 | 클래스 불균형 해소, 사기 Recall 향상 |
| 손실함수 | CrossEntropy | FocalLoss(γ=2.0) | 위장 리뷰 등 어려운 케이스 집중 학습 |

**최종 효과**: PR-AUC 0.2739 → 0.8674 (+216.6%), Macro F1 0.1956 → 0.7666 (+291.9%)

### 7.3 실무 활용 방안

#### 활용 방안 1: 실시간 사기 리뷰 모니터링 시스템

PC-GNN은 단일 리뷰가 아닌 **리뷰 네트워크 전체를 고려**하여 판단합니다. 이를 실무에 적용하면, 새 리뷰가 등록될 때 기존 그래프에 연결하여 위험 점수(Risk Score)를 실시간으로 계산하는 모니터링 대시보드를 구축할 수 있습니다.

- **입력**: 신규 리뷰 텍스트, 작성자, 별점, 작성 시점
- **처리**: 기존 R-U-R, R-Sim-R 엣지로 그래프에 연결 → GNN 추론
- **출력**: 사기 확률 점수(0~1), 어텐션 기반 의심 이유 설명

#### 활용 방안 2: 설명 가능한 사기 탐지 (XAI)

Chooser Attention 가중치는 "왜 이 리뷰가 사기로 판별됐는가"를 설명하는 근거로 활용할 수 있습니다.

- **R-U-R Attention이 높음** → "이 리뷰어의 다른 리뷰들과 패턴이 동일함"
- **R-Sim-R Attention이 높음** → "다른 사기 리뷰들과 거의 같은 문구를 사용함"
- **R-P-R Attention이 높음** → "같은 식당의 다른 의심 리뷰들과 함께 몰아서 작성됨"

이처럼 어텐션 가중치가 탐지 근거의 **자연어 설명**으로 바로 변환 가능하여, 플랫폼 운영자가 사기 판별 결과를 신뢰하고 검토할 수 있는 근거를 제공합니다.

#### 활용 방안 3: 리뷰 검토 우선순위화 (Human-in-the-Loop)

사기 확률 점수를 기준으로 **검토 우선순위 큐(Queue)** 를 구성합니다.

- 사기 확률 > 0.8: 즉시 자동 숨김 또는 최우선 수동 검토
- 사기 확률 0.5~0.8: 플래그 처리 후 검토 대기열 등록
- 사기 확률 < 0.5: 정상 처리

현재 모델의 사기 클래스 Recall 0.84는 실제 사기 리뷰의 84%를 탐지한다는 의미로, 이 수준이면 플랫폼 운영자의 수동 검토 부담을 84% 감소시킬 수 있습니다.
