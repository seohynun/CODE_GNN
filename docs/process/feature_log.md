# 피처 엔지니어링 로그

## 데이터 샘플링 전략 (GNN 연결성 및 도메인 지식 기반)

> GNN 모델의 학습 효율과 연결 패턴 보존을 위해 `01_Data_Preprocessing.ipynb`에서 수행하는 핵심 샘플링 전략을 기록한다.

---

### 1. 공간적 배경 최적화 (상위 300개 식당)

**전략**
전체 식당을 대상으로 하는 대신, 리뷰 수가 가장 많은 **상위 300개 식당**으로 무대를 좁힌다.

**근거**
리뷰가 흩어져 있으면 노드 간의 연결(R-P-R, R-T-R 등)이 끊어져 GNN이 관계 정보를 학습하기 어렵다. 데이터가 충분히 모여 있는 밀집 지역을 선택함으로써 그래프의 연결성(Connectivity)을 극대화한다.

---

### 2. 사기 유저 타겟팅 (전수 추출)

**전략**
단순히 '사기 라벨(label=1)이 붙은 리뷰'만 추출하는 것이 아니라, 사기 리뷰를 한 번이라도 쓴 유저를 색출한 뒤 그 유저가 쓴 **'모든' 리뷰**를 통째로 가져온다.

**근거**
사기꾼은 정체를 숨기기 위해 정상적인 리뷰를 섞어서 작성하는 '위장(Camouflage)' 전술을 사용한다. 이 유저의 모든 리뷰를 가져와야만 사기꾼이 정상인 척 남긴 리뷰들까지 포함된 온전한 **유저 행동망(R-U-R)**을 파악할 수 있다.

---

### 3. 활성 정상 유저 타겟팅 (헤비 유저 중심)

**전략**
정상 리뷰를 추출할 때, 리뷰를 **3개 이상 작성한 '활성 유저(Active User)'**의 데이터만 포함한다.

**근거**
리뷰를 단 1개만 달고 사라진 유저는 네트워크 상에서 고립된 노드(Isolated Node)가 되어 선(Edge)을 만들지 못한다. 이러한 데이터는 GNN 학습에 유의미한 구조적 정보를 제공하지 못하고 오히려 노이즈가 될 수 있으므로, 최소한의 연결성을 보장하는 활성 유저에 집중한다.

---

## 파생변수가 GNN에서 작동하는 원리

### 1. 파생변수가 들어가는 위치: 노드 피처 벡터

GNN에서 각 노드(리뷰)는 하나의 숫자 벡터로 표현된다.

```
리뷰 하나 = [rating, is_fraud_user, user_fraud_ratio, ..., 텍스트64차원]
              ↑ 수치 피처 (10차원)                      ↑ 텍스트 피처
                            합쳐서 74차원 벡터
```

파생변수는 이 벡터의 앞부분을 구성한다. 즉 **그래프 구조를 태우기 전, 각 리뷰 노드가 자기 자신을 설명하는 초기값**으로 사용된다.

---

### 2. GNN이 이 벡터를 어떻게 활용하는가

GNN의 핵심은 **이웃 노드들의 정보를 집계(aggregate)** 하는 것이다. 2-layer 모델이면 2홉(hop) 이내 이웃까지 본다.

```
[학습 예시]

리뷰 A (사기, user_burst_max7d=15)
    │ R-U-R 엣지 (같은 사용자)
    ▼
리뷰 B (정상처럼 보임, 텍스트 무난, 별점 4점)

→ GraphSAGE: B의 표현 = f(B 자신의 벡터, A의 벡터 집계)
→ B 혼자 보면 정상이지만, 이웃 A가 burst가 높으니
  "이 사용자의 다른 리뷰들은 조직적 특성을 가짐"을 학습
```

**노드 피처(파생변수)가 엣지(관계)를 타고 이웃에게 전파**된다.

---

### 3. 각 파생변수가 성능에 기여하는 원리

| 파생변수 | 인코딩하는 정보 | GNN에서의 역할 |
|----------|----------------|----------------|
| `is_fraud_user` | 이 사용자는 훈련 데이터에서 사기를 친 적 있는가 | 사기 리뷰어의 모든 리뷰 노드에 강한 초기 신호 부여 |
| `user_fraud_ratio` | 이 사용자 리뷰 중 몇 %가 사기인가 | R-U-R 이웃 전파 시 조직 수준의 사기 강도 전달 |
| `user_burst_max7d` | 7일 안에 최대 몇 개 리뷰를 몰아 썼나 | 폭발적 리뷰 작성 패턴을 개별 노드에 각인 |
| `user_review_count` | 이 사용자가 얼마나 많이 썼나 | 과도하게 활동적인 사용자 식별 |
| `user_avg_rating` / `user_rating_std` | 별점이 편향되어 있거나 불규칙한가 | 극단적 별점 패턴 탐지 |
| `weekday` / `month` | 언제 작성되었나 | R-T-R 엣지와 결합해 특정 시간대 집중 공격 탐지 |

---

## 파생변수 상세 설명

> 베이스라인(`rating` + 텍스트)을 제외한 모든 파생변수의 정의, 계산 방법, 사기 탐지 근거를 기록한다.

---

### `is_fraud_user` — 사기 리뷰어 여부

**정의**
해당 리뷰를 작성한 사용자가, 훈련 데이터 기준으로 사기 리뷰(`label=1`)를 단 한 건이라도 작성한 적 있는가를 나타내는 이진(0/1) 변수.

**계산 방법**
```python
fraud_user_set_train = set(df_train.loc[df_train["label"] == 1, "user_id"])
df_sub["is_fraud_user"] = df_sub["user_id"].isin(fraud_user_set_train).astype(int)
```
훈련 데이터에서만 사기 리뷰어 집합을 구성한다. 테스트/검증 노드의 라벨은 참조하지 않는다.

**사기 탐지 근거**
조직적 사기는 동일 사용자가 반복적으로 사기 리뷰를 작성하는 형태로 나타난다. 한 번이라도 사기 리뷰를 작성한 사용자는 해당 사용자가 쓴 다른 리뷰들(정상으로 위장한 것 포함)도 조직 내 행위일 가능성이 높다.

**GNN에서의 기여**
R-U-R 엣지로 연결된 같은 사용자의 모든 리뷰 노드가 초기 벡터에 `is_fraud_user=1`을 공유한다. 메시지 패싱 과정에서 이 신호가 이웃 노드에 전파되어, 같은 사용자의 다른 리뷰들이 강하게 사기 방향으로 표현된다.

---

### `user_review_count` — 사용자 총 리뷰 수

**정의**
해당 리뷰를 작성한 사용자가 서브그래프 내 훈련 데이터에서 작성한 총 리뷰 수.

**계산 방법**
```python
user_stats_train = df_train.groupby("user_id").agg(
    user_review_count = ("label", "count"),
    ...
)
```

**사기 탐지 근거**
일반 소비자는 특정 레스토랑에 리뷰를 자주 쓰지 않는다. 단기간에 동일 지역·동일 카테고리에 리뷰를 대량으로 쏟아내는 사용자는 조직적 사기 리뷰어일 가능성이 높다. YelpZip 데이터에서도 사기 리뷰어의 평균 리뷰 수가 정상 사용자보다 현저히 높다.

**GNN에서의 기여**
노드 자체의 "활동량"을 인코딩한다. `user_burst_max7d`와 결합하면 "많이 썼고, 그것이 단기간에 몰렸다"는 복합 패턴을 모델이 학습할 수 있다.

---

### `user_fraud_ratio` — 사용자 사기 리뷰 비율

**정의**
해당 리뷰를 작성한 사용자의 훈련 데이터 내 전체 리뷰 중 사기 리뷰(`label=1`)가 차지하는 비율.

**계산 방법**
```python
user_stats_train = df_train.groupby("user_id").agg(
    user_fraud_ratio = ("label", "mean"),  # 평균 = 비율
    ...
)
# 훈련 데이터에 없는 사용자는 0으로 채움
df_sub["user_fraud_ratio"] = df_sub["user_fraud_ratio"].fillna(0.0)
```

**사기 탐지 근거**
`user_fraud_ratio=0.8`이면 이 사용자가 쓴 리뷰 80%가 사기다. 이 수치가 높을수록 해당 사용자의 모든 리뷰가 의심스럽다. 특히 리뷰 수가 적고 비율이 높은 사용자는 특정 캠페인을 위해 생성된 계정일 가능성이 높다.

**GNN에서의 기여**
`is_fraud_user`가 이진 신호라면, `user_fraud_ratio`는 연속형 신호로 사기 강도를 표현한다. 두 피처가 동시에 높은 노드는 GNN에서 강한 사기 표현을 가지게 되고, R-U-R 이웃을 통해 같은 사용자의 다른 리뷰에도 이 강도가 전달된다.

---

### `user_avg_rating` — 사용자 평균 별점

**정의**
해당 리뷰를 작성한 사용자가 훈련 데이터에서 부여한 별점(1~5)의 평균.

**계산 방법**
```python
user_stats_train = df_train.groupby("user_id").agg(
    user_avg_rating = ("rating", "mean"),
    ...
)
# 훈련 데이터에 없는 사용자는 전체 평균으로 채움
df_sub["user_avg_rating"] = df_sub["user_avg_rating"].fillna(df_train["rating"].mean())
```

**사기 탐지 근거**
사기 리뷰어는 특정 레스토랑을 집중 공격(1점 폭탄) 또는 집중 홍보(5점 도배)하는 경향이 있다. 정상 사용자의 평균 별점은 다양한 레스토랑에 걸쳐 분포하지만, 사기 리뷰어의 평균 별점은 한쪽 극단에 치우친 경우가 많다.

**GNN에서의 기여**
`user_rating_std`와 함께 사용하면 "평균이 낮고(또는 높고) 표준편차도 낮다" = 별점 패턴이 일관되게 극단적이다 라는 패턴을 모델이 포착할 수 있다.

---

### `user_rating_std` — 사용자 별점 표준편차

**정의**
해당 리뷰를 작성한 사용자가 훈련 데이터에서 부여한 별점의 표준편차.

**계산 방법**
```python
user_stats_train = df_train.groupby("user_id").agg(
    user_rating_std = ("rating", lambda x: float(x.std()) if len(x) > 1 else 0.0),
    ...
)
```
리뷰가 1건뿐인 사용자는 표준편차를 계산할 수 없으므로 0으로 처리한다.

**사기 탐지 근거**
- **표준편차가 매우 낮은 경우**: 모든 리뷰에 같은 별점을 부여 → 자동화된 사기 봇 가능성
- **표준편차가 매우 높은 경우**: 별점을 무작위로 섞어서 탐지를 회피하려는 시도 가능성

두 경우 모두 정상 사용자의 자연스러운 리뷰 패턴과 다르다.

**GNN에서의 기여**
`user_avg_rating`과 함께 사용자 수준의 별점 행동 패턴을 2차원으로 표현한다. 모델은 이 두 피처의 조합으로 별점 기반 사기 유형을 구분할 수 있다.

---

### `weekday` — 리뷰 작성 요일

**정의**
해당 리뷰가 작성된 날의 요일 (0=월요일 ~ 6=일요일).

**계산 방법**
```python
df_sub["weekday"] = df_sub["date"].dt.weekday.astype(float)
```

**사기 탐지 근거**
EDA 분석 결과, 사기 리뷰는 특정 요일에 집중되는 경향이 있었다(수·목·금 비율이 상대적으로 높음). 사기 캠페인이 특정 마케팅 일정에 맞춰 조직적으로 실행되기 때문으로 보인다.

**GNN에서의 기여**
R-T-R 엣지(같은 주에 작성된 리뷰 연결)와 함께 작용한다. 같은 주, 같은 요일에 몰린 리뷰들이 R-T-R 엣지로 연결되면서, 시간적 집중 패턴이 그래프 구조와 노드 피처 양쪽에서 동시에 반영된다.

---

### `month` — 리뷰 작성 월

**정의**
해당 리뷰가 작성된 날의 월 (1~12).

**계산 방법**
```python
df_sub["month"] = df_sub["date"].dt.month.astype(float)
```

**사기 탐지 근거**
EDA 분석 결과, 2014년 하반기(7~12월)에 사기 리뷰 버스트가 집중적으로 발생했다. 월 정보를 피처로 사용하면 모델이 사기 활동이 활발했던 계절적 패턴을 학습할 수 있다.

**GNN에서의 기여**
`weekday`와 마찬가지로 R-T-R 엣지와 결합되어 시간 기반 사기 클러스터를 강화한다. 특정 월에 동일 레스토랑에 몰린 리뷰들이 연결망 안에서 서로를 강화하는 방향으로 표현이 학습된다.

---

### `user_burst_max7d` — 7일 이내 최대 리뷰 수

**정의**
해당 리뷰를 작성한 사용자가, 임의의 7일 윈도우 안에서 작성한 최대 리뷰 수.

**계산 방법**
```python
# burst_analysis.py에서 계산 후 burst_features.csv로 저장
# 슬라이딩 윈도우 방식
for i in range(len(dates)):
    window_end = dates[i] + np.timedelta64(7, "D")
    cnt = int(np.sum(dates[i:] <= window_end))
    max_in_window = max(max_in_window, cnt)
```

**사기 탐지 근거**
EDA 분석 결과, 사기 리뷰어의 `user_burst_max7d` 평균은 **1.014**, 정상 리뷰어는 **0.057**로 약 **18배** 차이가 났다. 사기 조직은 특정 캠페인 기간에 집중적으로 리뷰를 쏟아내는 방식으로 운영되기 때문에, 이 값이 높으면 조직 리뷰어일 가능성이 매우 높다.

**GNN에서의 기여**
현재 파생변수 중 사기 탐지력이 가장 강한 단일 피처다. 노드 초기 벡터에 이 신호가 포함되면, 메시지 패싱을 통해 같은 사용자의 다른 리뷰 노드에도 "이 사용자는 단기 집중 작성자" 정보가 전파된다.

---

### `user_burst_ratio` — 7일 집중도 비율

**정의**
`user_burst_max7d`를 해당 사용자의 전체 리뷰 수로 나눈 값. 전체 리뷰 중 7일 집중 구간이 차지하는 비율.

**계산 방법**
```python
burst_ratio = max_in_window / total_reviews
```

**사기 탐지 근거**
`user_burst_max7d`만으로는 리뷰 수가 많은 정상 파워 유저와 사기 리뷰어를 구분하기 어려울 수 있다. `user_burst_ratio`는 "전체 활동 대비 얼마나 집중적인가"를 측정하여 이 한계를 보완한다.

예시:
- 사용자 A: 전체 5건 중 5건이 7일 이내 → `burst_ratio = 1.0` (완전 집중)
- 사용자 B: 전체 100건 중 10건이 7일 이내 → `burst_ratio = 0.1` (분산)

**GNN에서의 기여**
`user_burst_max7d`와 쌍을 이루어 버스트 패턴의 절대량과 상대적 집중도를 동시에 표현한다. 두 피처가 모두 높은 노드는 매우 강한 단기 집중 신호를 가지며, 모델이 이를 사기의 강력한 증거로 학습한다.

---

### 4. 베이스라인 vs 전체 피처, 왜 성능 차이가 나는가

```
베이스라인 (rating + text만)
→ "이 리뷰 텍스트가 수상하게 보이는가?"만 판단
→ 사기조직이 자연스러운 텍스트를 쓰면 탐지 불가

전체 피처 (파생변수 포함)
→ "이 리뷰 자체" + "이 리뷰를 쓴 사람의 행동 패턴"을 동시에 판단
→ 텍스트가 자연스러워도 user_burst_max7d=20이면 의심
→ 게다가 같은 사용자의 다른 리뷰들도 R-U-R 엣지로 연결되어
  서로가 서로를 강화하는 방향으로 표현이 학습됨
```

**요약:** 파생변수는 "텍스트만으로 숨길 수 있는 사기 패턴"을 사용자 행동 이력과 시간 패턴으로 보완하고, GNN의 메시지 패싱이 그 신호를 같은 조직 내 다른 리뷰들에게 전파하기 때문에 성능이 오른다.

## 텍스트 기반 파생 피처 (섹션 2-7 EDA 분석)

> 리뷰 텍스트에서 직접 추출한 10개 피처. EDA에서 사기/정상 간 통계적 유의성 확인 완료(Mann-Whitney U 검정).
> GNN 노드 피처로 추가 시 `num_cols`에 해당 컬럼명을 넣으면 자동 반영된다.

---

### `text_len` — 텍스트 길이(문자 수)

**정의**
리뷰 텍스트 전체의 문자 수.

**계산 방법**
```python
len(str(text))
```

**사기 탐지 근거**
정상 리뷰어는 실제 경험을 구체적으로 서술하는 반면, 사기 리뷰는 짧고 모호한 경향이 있다. EDA에서 정상 리뷰의 평균 텍스트 길이가 사기 리뷰보다 유의미하게 길었다(p<0.01).

**GNN에서의 기여**
단독으로는 약한 신호이지만, `menu_mentions`·`word_count`와 결합하면 "짧고 메뉴 언급 없고 단어 수도 적은" 사기 특유의 클러스터를 구분하는 데 기여한다. R-P-R 커스텀 엣지의 정의 조건(35th percentile 이하) 중 하나로 사용된다.

---

### `word_count` — 단어 수

**정의**
리뷰 텍스트를 공백 기준으로 분리한 단어의 총 개수.

**계산 방법**
```python
len(str(text).split())
```

**사기 탐지 근거**
`text_len`과 유사하지만 문장 구조를 더 잘 반영한다. 단어 수가 적으면 문장이 단순하고 정보 밀도가 낮다는 의미로, 사기 리뷰의 "짧고 피상적인 칭찬" 패턴과 연결된다.

**GNN에서의 기여**
`text_len`과 함께 리뷰의 "정보량"을 2차원으로 표현한다. 두 피처가 모두 낮은 노드는 사기 방향으로 강한 초기 신호를 가진다.

---

### `digit_ratio` — 숫자 비율

**정의**
텍스트 전체 문자 중 숫자(`0`~`9`) 문자가 차지하는 비율.

**계산 방법**
```python
sum(c.isdigit() for c in text) / max(len(text), 1)
```

**사기 탐지 근거**
EDA 사전 분석에서 확인된 3대 핵심 패턴 중 하나. 정상 리뷰어는 가격("$12"), 인원수("4 of us"), 대기 시간("30 minutes") 등 구체적인 수치를 자주 언급한다. 사기 리뷰는 이런 구체적 경험 묘사가 없어 숫자 사용 빈도가 낮다.

**GNN에서의 기여**
`menu_mentions`와 함께 "실제 방문 경험의 구체성"을 정량화한다. 두 피처가 모두 낮으면 허위 리뷰 가능성이 높으며, 메시지 패싱으로 같은 사용자·같은 시간대 리뷰에 이 신호가 전파된다.

---

### `menu_mentions` — 메뉴 언급 횟수

**정의**
텍스트에서 사전 정의된 60여 개 음식·메뉴 키워드가 등장한 횟수.

**계산 방법**
```python
MENU_WORDS = {"chicken", "beef", "pizza", "salad", ...}  # 60+ 단어
sum(1 for w in text.lower().split() if w in MENU_WORDS)
```

**사기 탐지 근거**
EDA 사전 분석에서 확인된 3대 핵심 패턴 중 하나. 실제 방문한 고객은 먹은 음식을 자연스럽게 언급한다("the grilled chicken was amazing"). 사기 리뷰어는 특정 음식을 먹지 않았거나 대량으로 제작된 템플릿 텍스트를 사용하므로 메뉴 언급이 드물다.

**GNN에서의 기여**
R-P-R 커스텀 엣지 정의 조건(menu_cnt == 0) 중 하나로 직접 사용된다. 즉 이 피처가 0인 노드들이 의심 텍스트 패턴 그룹으로 묶여 별도의 엣지로 연결된다.

---

### `special_ratio` — 특수기호 비율

**정의**
텍스트 전체 문자 중 영숫자와 공백을 제외한 특수기호(`!`, `@`, `#`, `.` 등)가 차지하는 비율.

**계산 방법**
```python
sum(not c.isalnum() and not c.isspace() for c in text) / max(len(text), 1)
```

**사기 탐지 근거**
사기 리뷰는 감탄부호·이모티콘·별표 등 특수기호를 과도하게 사용하는 경향이 있다("Great food!!! ★★★"). 이는 인위적 열정을 표현하거나 자동화 생성 텍스트의 특성과 연결된다.

**GNN에서의 기여**
`excl_count`와 상호 보완적이다. 느낌표를 제외한 다양한 특수기호 패턴을 포착하여, 모델이 사기 리뷰의 "과도한 부호 사용" 경향을 학습하도록 돕는다.

---

### `upper_ratio` — 대문자 비율

**정의**
텍스트의 영문자 중 대문자가 차지하는 비율.

**계산 방법**
```python
sum(c.isupper() for c in text if c.isalpha()) / max(sum(c.isalpha() for c in text), 1)
```

**사기 탐지 근거**
⚠️ **[EDA 재검토 결과 수정]** 텍스트 피처 EDA(Mann-Whitney U)에서 **p=0.445 (ns)** 로 통계적으로 유의미하지 않았다. Cohen's d=+0.022로 효과 크기도 매우 작다. YelpZip 서브그래프에서는 사기/정상 리뷰 간 대문자 사용 패턴이 실질적으로 구분되지 않는다.

**GNN에서의 기여**
세 가지 [ns] 피처(`upper_ratio`, `excl_count`, `avg_word_len`) 중 효과 크기가 가장 작아 노이즈 기여 가능성이 가장 높다. 추후 ablation study 시 가장 먼저 제거를 검토해야 할 피처다.

---

### `ttr` — 단어 다양성(Type-Token Ratio)

**정의**
전체 단어 수 대비 고유 단어 수의 비율. 값이 높을수록 어휘가 다양하다.

**계산 방법**
```python
len(set(words)) / max(len(words), 1)
```

**사기 탐지 근거**
EDA에서 통계적으로 유의미하였으나(p<0.01, d=+0.279), **방향이 직관과 반대**다. Cohen's d가 양수(+0.279)라는 것은 사기 리뷰의 TTR이 정상 리뷰보다 높다는 의미인데, 이는 진짜 어휘 다양성 때문이 아니라 **길이 편향(length bias)** 때문이다. 사기 리뷰는 짧기 때문에(text_len 평균 477 vs 정상 654) 단어 수 분모가 작아 자연스럽게 TTR이 높아진다. 즉 TTR이 포착하는 신호는 "어휘가 다양한 사기 리뷰"가 아니라 "짧은 리뷰 = 사기"라는 text_len 신호의 반영일 가능성이 높다.

**GNN에서의 기여**
독립적 신호보다는 `text_len`·`word_count`와 중복된 신호를 담는 피처다. 모델이 이 관계를 학습할 수 있으나, 해석 시 "TTR이 높을수록 사기"라는 직접적 해석은 주의해야 한다.

---

### `excl_count` — 느낌표 수

**정의**
텍스트에서 느낌표(`!`)가 등장한 절대 횟수.

**계산 방법**
```python
str(text).count("!")
```

**사기 탐지 근거**
⚠️ **[EDA 재검토 결과 수정]** 텍스트 피처 EDA(Mann-Whitney U)에서 **p=0.365 (ns)** 로 통계적으로 유의미하지 않았다. 사기/정상 리뷰 간 느낌표 수 차이가 실제로는 미미하며, Cohen's d 효과 크기도 매우 작다. 이전에 유의미하다고 기록한 내용은 서브그래프 추출 이전의 전체 데이터 기준 결과로, 현재 서브그래프에서는 재현되지 않는다.

**GNN에서의 기여**
노이즈 피처로 작용할 가능성이 있다. `special_ratio`가 이미 느낌표를 포함한 특수기호 전반을 포착하고 있으므로, 추후 피처 선별(ablation) 시 제거 우선 후보다.

---

### `avg_word_len` — 평균 단어 길이

**정의**
텍스트를 구성하는 단어들의 평균 문자 길이.

**계산 방법**
```python
sum(len(w) for w in words) / max(len(words), 1)
```

**사기 탐지 근거**
⚠️ **[EDA 재검토 결과 수정]** 텍스트 피처 EDA(Mann-Whitney U)에서 **p=0.684 (ns)** 로 통계적으로 유의미하지 않았다. 정상/사기 리뷰 간 평균 단어 길이 차이가 현재 서브그래프에서는 거의 없다. 이론적 근거("긴 단어 = 어휘 풍부")는 개별 사례에서는 성립하지만 집단 평균에서 차이가 사라진다.

**GNN에서의 기여**
노이즈 피처로 작용할 가능성이 있다. `ttr`이 어휘 복잡도를 이미 포착하고 있으므로, 추후 피처 선별(ablation) 시 제거 우선 후보다.

---

### `sentiment` — 감성 점수

**정의**
긍정 단어 출현 횟수에서 부정 단어 출현 횟수를 뺀 값을 전체 단어 수로 정규화한 점수.

**계산 방법**
```python
POS_WORDS = {"great", "amazing", "delicious", ...}  # 27개
NEG_WORDS = {"bad", "terrible", "awful", ...}       # 30개
(pos_count - neg_count) / max(word_count, 1)
```

**사기 탐지 근거**
EDA 사전 분석에서 확인된 3대 핵심 패턴과 연결된다. 사기 리뷰는 극단적으로 긍정적인 경향이 있어 감성 점수가 높다. 정상 리뷰는 음식에 대한 현실적인 평가를 포함하여 감성이 상대적으로 중립적이다. R-P-R 커스텀 엣지 정의 조건(65th percentile 이상)으로 직접 사용된다.

**GNN에서의 기여**
R-P-R 엣지 조건 중 하나로 직접 그래프 구조에 반영된다. 또한 노드 피처로 포함되면 감성 신호가 R-U-R·R-T-R 엣지를 타고 같은 사용자·같은 시간대 리뷰에 전파되어, 조직 내 "긍정 도배" 패턴을 GNN이 학습하도록 돕는다.

### 📊 v2 결과 유의미성 평가

#### 결론: **조건부 유의미 — PR-AUC 관점에서는 퇴보, F1 관점에서는 개선**

#### 1. 텍스트 EDA 결과의 유의미성

텍스트 피처 10개에 대한 Mann-Whitney U 검정(v1에서 반영됨) 결과:

| `word_count` | 7.71e-257 | ** | -0.306 | 정상>사기 | 사기 리뷰의 단어 수가 유의미하게 적음 |
| `menu_mentions` | 3.83e-214 | ** | -0.323 | 정상>사기 | **가장 큰 효과 크기**, 사기 리뷰는 메뉴 언급 적음 |
| `digit_ratio` | 2.83e-68 | ** | -0.064 | 정상>사기 | 효과 크기 작음, 방향은 유효 |

**7개 유의미 / 3개 비유의미** → 텍스트 피처 전체로서는 근거 있으나, 3개는 모델에 노이즈를 추가할 수 있음.

#### 2. v2(+분산) 결과가 엇갈린 이유

**PR-AUC 감소(-0.0153):**
- PR-AUC는 소수 클래스(사기)에 대한 정밀도-재현율 균형을 측정한다.
- v2의 화이트리스트(`activity_span ≥ 180d` 등) 조건이 일부 실제 사기 유저를 정상으로 오분류할 수 있다.
- 화이트리스트 기준이 너무 너그러우면 R-P-R 엣지가 약화되어 사기 탐지 정밀도가 떨어진다.

**Macro F1 증가(+0.0268):**
- Macro F1은 정상/사기 클래스 F1 평균을 동일 가중치로 본다.
- 화이트리스트로 장기 정상 사용자의 오탐이 줄어 **정상 클래스 F1이 개선**된 것이 반영된 결과다.
- 그러나 이것이 사기 탐지 성능의 실질적 향상을 의미하지는 않는다.

#### 3. 사기 탐지 과제에서의 해석

```
사기 탐지의 핵심 지표 = PR-AUC
이유: 데이터 불균형(사기 << 정상) 환경에서
     사기를 얼마나 높은 정밀도로 잡아내는가가 핵심 목표이기 때문

→ PR-AUC 기준: v2(-0.0153) < v1  ← 퇴보
→ Macro F1 기준: v2(+0.0268) > v1 ← 개선 (but 정상 클래스 개선이 주요 원인)
```

### v3 — Logic 1 Ablation + Logic 2 Defense + Logic 3 (초기 적용 → 부분 롤백)

#### 3-1. 적용 내용

**Logic 1 (Ablation)**
- `upper_ratio`, `excl_count`, `avg_word_len` 제거 (EDA Mann-Whitney 결과 3개 모두 ns)
- V1_COLS: 19개 → 16개

**Logic 2 (Defense Logic)**
- 화이트리스트 강화: `activity_span ≥ 180d AND prod_diversity ≥ 3 AND user_review_count ≥ 20` → **`activity_span ≥ 365d AND user_review_count ≥ 10`**
  - 기존 3조건은 상호 중복이 있고 prod_diversity가 서브그래프 내에서 희석될 수 있어 단순화
  - 1년 이상 활동한 사용자를 충성 고객으로 정의, 리뷰 10개 이상으로 단일 조건 강화
- **Soft Discount** 도입: 각 노드의 신뢰 점수(`trust_score`) 계산 후 커스텀 엣지(KNN + R-P-R)에 기하평균 가중치 부여
  - `trust_score = clip(activity_span/365, 0, 1) × 0.5 + clip(user_review_count/10, 0, 1) × 0.5`
  - GAT `edge_dim=1` 설정으로 엣지 가중치를 attention 연산에 직접 반영
  - 저신뢰 노드끼리의 의심 엣지일수록 attention 감쇄

**Logic 3 (Feature & Loss) — 초기 적용**
- `avg_text_similarity_of_past_reviews` 피처 추가: 동일 사용자 리뷰 간 코사인 유사도 평균 (TF-IDF SVD 64차원 기반)
- Focal Loss 도입 (`gamma=2.0`): 하드 샘플 패널티 강화

#### 3-2. 초기 v3 결과

| 버전 | 피처 수 | PR-AUC | Macro F1 |
|------|---------|--------|----------|
| Baseline | 65 | 0.3116 | 0.5029 |
| v1 (+행동/버스트) | 84 | 0.5612 | 0.7096 |
| v2 (+분산) | 90 | 0.5539 | 0.7164 |
| **v3 초기 (Logic1+2+3)** | 88 | **0.5164** | **0.7093** |
| v3 vs v2 변화 | -2 | **-0.0375** | -0.0071 |

→ PR-AUC가 v2 대비 -0.0375 하락. v2보다 성능이 떨어지는 결과.

#### 3-3. 원인 분석 및 Fix

**Fix 1 — avg_text_sim 제거 (Logic 3 Feature 롤백)**

- **원인**: TF-IDF + SVD 64차원은 단어 빈도 기반으로 의미론적 유사도 해상도가 낮음. 봇의 템플릿 재사용을 실제로 잡아내지 못하고 노이즈만 추가
- **조치**: `V3_COLS = []` — `avg_text_sim` 완전 제거. Cell 37의 계산 코드는 EDA 분석 기록 보존을 위해 유지

**Fix 2 — Focal Loss 제거 (Logic 3 Loss 롤백), CrossEntropyLoss 복귀**

- **원인**: Focal Loss(하드 샘플 집중)와 Soft Discount(저신뢰 노드 엣지 감쇄)가 동시에 작동할 때 방향 충돌
  - Focal Loss: "불확실한 사기 노드에 더 집중하라"
  - Soft Discount: "저신뢰(= 의심) 노드의 엣지 정보를 줄여라"
  - 사기 노드 = 저신뢰 노드가 겹치는 경우, 두 로직이 확률 공간을 반대로 당김
- **조치**: `criterion = nn.CrossEntropyLoss(weight=class_weight)` 복귀. Soft Discount는 독립 작동이므로 유지

#### 3-4. v3 최종 구성 (Fix 후)

| 항목 | 내용 |
|------|------|
| 피처 | BASE(1) + V1_ablated(16) + V2(6) + V3(0) = **수치 23개** + 텍스트 64차원 = 87차원 |
| 제거된 피처 | `upper_ratio`, `excl_count`, `avg_word_len`, `avg_text_sim` |
| 유지된 변경 | Soft Discount (trust_score 기반 GAT edge_attr), 강화된 화이트리스트 |
| 손실 함수 | CrossEntropyLoss (class_weight 유지) |

> v3 Fix 후 성능은 재실행 필요. 예상 방향: Soft Discount 단독 효과로 v2 대비 소폭 개선 또는 동등.
