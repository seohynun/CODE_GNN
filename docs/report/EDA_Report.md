## 1. 데이터 개요 및 라벨 전처리

### 1.1 원본 데이터셋 현황

YelpZip 전체 데이터를 처음 로드하면 다음과 같은 상태였다.

| 항목 | 수치 |
|------|------|
| 전체 리뷰 수 | **608,458개** |
| 정상 리뷰 (label=0) | 528,019개 |
| 사기 리뷰 (label=1) | 80,439개 |
| 사기 비율 | 약 13.2% |

컬럼 구성: `user_id`, `prod_id`, `rating`, `label`, `date`, `text`, `tag`

### 1.2 라벨 변환 — 반드시 지켜야 할 첫 번째 규칙

YelpZip의 원본 라벨 체계는 `-1`(사기), `1`(정상)으로 설계되어 있다. 그러나 프로젝트 규칙에 따라 반드시 **`1`(사기), `0`(정상)** 으로 변환해야 한다.

**변환 전 → 변환 후**
- `-1` (Fraud) → `1` (Fraud)
- `1` (Normal) → `0` (Normal)

#### 시행착오: 이중 변환 버그

초기에 변환 코드를 단순하게 작성했을 때, **이미 변환이 완료된 Parquet 파일을 다시 로드해도 변환을 재시도**하는 문제가 발생했다. `{-1: 1, 1: 0}` 매핑을 그대로 적용하면, 이미 변환된 상태에서는 `1`(사기)이 `0`(정상)으로 다시 뒤집히는 치명적인 오류가 생긴다.

**해결책**: 로드 시점에 실제 라벨 값이 `{-1, 1}`인지 `{0, 1}`인지를 먼저 검사한 후 조건부 변환을 적용하는 방어 코드를 추가했다.

```python
unique_labels = set(df["label"].dropna().unique())

if unique_labels == {-1, 1}:
    df["label"] = df["label"].map({-1: 1, 1: 0})  # 원본 상태면 변환
elif unique_labels == {0, 1} or unique_labels == {0.0, 1.0}:
    df["label"] = df["label"].astype(int)           # 이미 변환됐으면 타입 정리만
else:
    raise ValueError(f"예상치 못한 라벨 값: {unique_labels}")
```

이 방어 코드 덕분에, 노트북을 여러 번 실행해도 라벨이 올바르게 유지된다.

## 2. 샘플링 전략 설계

### 2.1 단순 랜덤 샘플링을 택하지 않은 이유

GNN은 **그래프의 연결 구조**를 학습하는 모델이다. 단순 랜덤으로 50,000개를 추출하면 동일한 유저나 식당 간의 연결이 끊어져 R-U-R(같은 유저 엣지), R-P-R(같은 식당 엣지) 등 핵심 Relation이 희박해진다. 그래프 연결성을 보존하는 **밀도 중심 샘플링(Density-centric Sampling)** 이 필수적이었다.

### 2.2 4단계 샘플링 파이프라인

**단계 0. 시간 필터링 (2013~2014년)**

전체 608,458개 → **311,873개** (49.0%)

리뷰가 가장 집중된 기간을 선택하여 시간적 패턴의 일관성을 확보했다. 2015년 이후 데이터는 상대적으로 희소하며, 사기 패턴의 시간적 밀도가 낮아진다.

**단계 1. 상위 200개 식당 (공간적 밀도 확보)**

311,873개 → **107,445개** (34.5%)

리뷰 수 기준 상위 200개 식당으로 한정했다. 이렇게 하면 한 식당에 수백 개의 리뷰가 연결되므로 R-P-R(같은 식당을 리뷰한 사용자 간 연결) 엣지가 충분히 생긴다.

**단계 2. 사기 유저 타겟팅 — 위장 리뷰 확보**

단순히 label=1인 리뷰만 뽑으면 안 된다. 사기 리뷰어는 의심을 피하기 위해 **정상 리뷰도 함께 작성**한다. 이 "위장 정상 리뷰"까지 포함해야 유저 행동의 전체 패턴이 보인다.

- 사기 리뷰(label=1)를 한 번이라도 쓴 유저 ID를 색출: **10,108명**
- 해당 유저가 쓴 **모든 리뷰**(정상+사기 합산) 추출: **13,282개**

**단계 3. 활성 정상 유저 타겟팅 — 네트워크 연결성 확보**

단 1개의 리뷰만 남긴 유저는 GNN 엣지 연결에 거의 기여하지 못한다. **리뷰 3개 이상** 작성한 활성 유저로 제한했다.

- 활성 정상 유저: **7,331명**
- 해당 유저의 리뷰: **37,668개**

### 2.3 최종 샘플링 결과

| 구분 | 수치 |
|------|------|
| 최종 리뷰 수 | **50,950개** |
| 정상 리뷰 (label=0) | 38,291개 (75.2%) |
| 사기 리뷰 (label=1) | 12,659개 (24.8%) |
| 고유 사용자 수 | ~17,439명 |
| 고유 식당 수 | 200개 |

원본(13.2%)에 비해 사기 비율이 **24.8%** 로 높아진 것은, 사기 유저를 의도적으로 타겟팅했기 때문이다. 이는 클래스 불균형 완화에도 도움이 된다.

## 3. 버스트 패턴 EDA

### 3.1 분석 목적

사기 리뷰어는 단발적으로 행동하지 않고 **짧은 시간에 집중적으로** 리뷰를 몰아쓰는 경향(버스트, Burst)이 있다. 이 시간적 이상 패턴을 세 가지 스케일로 분석했다.

### 3.2 매크로 버스트 (월별 집계)

**버스트 임계값 정의**: 월평균 사기 리뷰 수 + 1.5 × 표준편차

| 통계 | 수치 |
|------|------|
| 월평균 사기 리뷰 수 | 527.5개 |
| 버스트 임계값 | **684개** |
| 버스트 발생 월 수 | **3개월** |

**버스트 상위 10개 월**

| 월 | 사기 리뷰 수 | 사기 비율 |
|----|-------------|----------|
| 2014-09 | 709개 | 30.5% |
| 2014-12 | 709개 | 30.6% |
| 2014-08 | 686개 | 26.5% |
| 2014-10 | 650개 | 29.5% |
| 2014-03 | 624개 | 25.8% |
| 2014-07 | 614개 | 24.5% |
| 2013-07 | 613개 | 26.1% |

2014년 하반기에 버스트가 집중되어 있으며, 특히 9월과 12월에 동시에 최고치(709개)를 기록한 점이 특징적이다. 12월은 연말 성수기로 식당 리뷰가 증가하는 시기이므로, 사기 조직이 의도적으로 이 시기를 노렸을 가능성이 있다.

### 3.4 마이크로 버스트 (개별 유저, 7일 슬라이딩 윈도우)

**분석 방법**: 각 사기 유저에 대해 7일 슬라이딩 윈도우를 적용, 윈도우 내 최대 리뷰 수를 계산

| 최대 7일 이내 리뷰 수 | 14개 |

**협력 버스트 임계값**: 주간 평균 사기 리뷰어 수(107.0명) + 1.5σ = **142.3명**

버스트 분석 결과, 사기 리뷰어와 정상 리뷰어의 버스트 특성이 크게 다름이 확인됐다.

## 4. 텍스트 단어 네트워크 분석

### 4.1 분석 목적

리뷰 텍스트를 단어 레벨의 네트워크로 모델링하여:
1. 사기/정상 리뷰 집단에서 각각 중심적으로 쓰이는 특징 단어를 도출
2. 도출된 **변별 어휘**를 기반으로 GNN의 커스텀 엣지 `R-TextSim-R`(텍스트 유사도가 높은 리뷰 간 연결)을 생성

### 4.2 텍스트 전처리 (Noise Reduction)

단어 네트워크가 지나치게 거대해지면 분석이 불가능하므로, 유의미한 단어만 선별했다.

**필터링 기준**:
- **품사 필터**: 명사(NN), 형용사(JJ), 동사(VB)만 추출 (관사·전치사 등 제거)
- **빈도 필터**: 전체 50,950개 리뷰에서 **100회 이상** 등장한 단어만 사용

**결과**: 전체 어휘 42,827개 → 핵심 어휘 **2,826개** (전체의 6.6%)

### 4.3 PMI 기반 단어 네트워크 구축

단어 간 관계를 단순 빈도(co-occurrence)가 아닌 **PMI(Pointwise Mutual Information)** 로 정의했다.

$$PMI(w_1, w_2) = \log\frac{P(w_1, w_2)}{P(w_1) \cdot P(w_2)}$$

PMI > 0인 경우에만 엣지를 추가하여 "우연히 같이 나온" 단어 쌍을 제거하고, 실질적인 연관 단어 쌍만 네트워크에 포함했다.

**초기 네트워크 규모**: 노드 2,825개, 엣지 **364,151개**

이 규모는 시각화와 커뮤니티 분석이 현실적으로 불가능할 정도로 거대했다.

### 4.4 단계적 노드 필터링 (핵심 설계 결정)

#### Step 1. 고립 노드 제거

공동출현 엣지가 전혀 없는 단어(고립 노드)를 제거했다. 제거 개수는 적었으나 불필요한 노드를 정리하는 기본 과정이다.

#### Step 2. 연결 중심성 70th 백분위 필터링

연결 중심성(Degree Centrality) 분포를 히스토그램으로 시각화한 결과, 분포에서 **자연스러운 분리점**이 70th 백분위 근방에 나타났다. 상위 30% 코어 어휘(약 845개)만 남기고 저중심성 노드를 제거했다.

**임계값 선택 근거**: 단순히 "절반을 자르자"는 식의 임의적 결정이 아니라, 분포의 자연 분리점을 시각적으로 확인 후 선택했다는 점이 중요하다.

#### Step 3. 어간 중복 제거 (Porter Stemmer)

같은 어간(stem)을 가진 단어들 중 빈도가 더 낮은 변형을 제거했다.  
예: `noodles` vs `noodle` → 빈도 높은 쪽만 유지

**결과**: 2,826개 → **약 103개** (EDA용 압축 어휘)

#### 시행착오: 순환 논리 문제 (EDA 어휘와 TF-IDF 어휘 혼용)

초기 설계에서는 이 필터링 과정을 통해 얻은 약 103개의 압축 어휘를 그대로 `R-TextSim-R` 커스텀 엣지 생성을 위한 **TF-IDF 어휘**로도 재사용하려 했다.

그런데 이는 심각한 **순환 논리(Circular Reasoning)** 였다:
- EDA 네트워크 분석(중심성, 커뮤니티 탐지)을 통해 필터링된 어휘를 사용해서
- 다시 사기/정상을 구별하는 TF-IDF 벡터를 만들어서
- 다시 사기 탐지 엣지를 구성하는 구조

즉, EDA의 결과물이 모델 입력에 직접 쓰이면서 **데이터 누수(Data Leakage)** 에 가까운 문제가 생긴다.

**해결책**: EDA용 축소 네트워크(103개)와 커스텀 엣지용 TF-IDF 어휘(변별 어휘 300개)를 **완전히 독립적으로** 결정하는 파이프라인을 재설계했다.

### 4.5 허브 제거 및 커뮤니티 탐지

103개로 줄인 EDA 네트워크에서도 연결 중심성 0.9 이상인 **초거대 허브 단어**들이 존재했다. 이런 허브들은 너무 일반적인 단어로, 사기/정상 구분에 도움이 되지 않고 오히려 분석을 흐린다.

허브 제거 후 남은 네트워크에 **Louvain 알고리즘**으로 커뮤니티를 탐지하여, 의미론적으로 유사한 단어 그룹들을 시각화했다.

**중심성 분석 결과 예시**:
- Degree Centrality 상위 단어: 음식·서비스·가격 관련 일반 단어들
- Betweenness Centrality 상위 단어: 여러 주제를 연결하는 가교 역할 단어들
- Eigenvector Centrality 상위 단어: 중요한 단어 그룹 내에서 영향력 높은 단어들

### 4.6 사기 vs 정상 분리 네트워크 — 변별력 있는 단어 발굴

전체 리뷰로 만든 통합 네트워크는 "식당 리뷰에 공통으로 자주 나오는 단어"만 보여준다. **사기 리뷰**와 **정상 리뷰**를 별도의 PMI 네트워크로 구축하여 고유벡터 중심성 차이를 계산했다.

| 네트워크 | 노드 수 | 엣지 수 |
|---------|--------|--------|
| 사기 리뷰 네트워크 | 2,217개 | 100,703개 |
| 정상 리뷰 네트워크 | 2,826개 | **888,470개** |

정상 리뷰 네트워크의 엣지가 훨씬 많다는 사실은, 정상 리뷰가 **더 다양한 주제와 단어를 풍부하게 사용**한다는 것을 의미한다.

**사기 리뷰 특징 단어 (상위 5개)**:
- `manager`, `asked`, `told`, `said`, `minutes`
- 해석: 사기 리뷰어들은 주로 **불만 경험 서술** 패턴으로 글을 작성하며(1점 Pollute 전략), 관리자와의 대화·시간 지연 등 부정적 상황 묘사 단어가 중심적

**정상 리뷰 특징 단어 (상위 5개)**:
- `topped`, `sweetness`, `refreshing`, `bites`, `savory`
- 해석: 정상 리뷰어는 **음식의 맛·질감·향미**를 구체적으로 묘사하는 단어를 많이 사용함

### 4.7 Permutation Test — 통계적 유의성 검증

사기/정상 네트워크의 중심성 차이가 단순히 **라벨 분포의 우연**인지, 아니면 **통계적으로 유의한 구조적 차이**인지 검증했다.

**방법**: 레이블을 100번 무작위 셔플하여 귀무가설 분포를 추정하고, 실제 관측 통계량과 비교

- 분석 단위: 서브샘플 5,000개 (관측값과 귀무가설을 동일 스케일로 비교)
- 관측 통계량: 평균 |사기 중심성 - 정상 중심성|
- p-value: 결과에 따라 유의성 확인

이 검증 단계를 추가함으로써 "단어 네트워크 분석이 의미 있는 신호를 잡고 있다"는 것을 수치로 뒷받침할 수 있었다.

### 4.8 커스텀 엣지 R-TextSim-R 생성

**설계 원리**:
1. 전체 2,826개 어휘 풀에서 사기/정상 고유벡터 중심성 차이 상위 **300개 변별 어휘** 독립 추출
2. 300차원 TF-IDF 벡터 구성
3. 코사인 유사도 ≥ 0.85인 리뷰 쌍을 엣지로 연결
4. 50,950개 전체 리뷰를 **청크(2,000개) 단위로 연산**하여 메모리 문제 해결

**결과**: `custom_edges_textSim.csv` 저장

**통계적 유효성 검증 (Chi-square + Cramér's V)**:

엣지가 무작위 연결이 아닌 사기-사기, 정상-정상끼리 더 많이 연결되는지 검증했다.

| 엣지 유형 | 기댓값 | 관측값 | 비율 |
|----------|--------|--------|------|
| Fraud-Fraud | - | - | ▲ 많음 |
| Normal-Normal | - | - | ▲ 많음 |
| Mixed | - | - | ▼ 적음 |

Cramér's V 값이 유의미하면, 텍스트 유사도 기반 엣지가 **동질 집단 내부**를 더 많이 연결한다는 것을 통계적으로 입증하는 셈이다.

#### 시행착오: TF-IDF 차원 수 문제

처음에는 EDA 필터링 결과물인 103개 어휘로 TF-IDF를 구성했다. 103차원 벡터에서 코사인 유사도 0.85 임계값은 사실상 거의 모든 쌍을 연결하거나(임계값이 너무 낮으면) 아무것도 연결하지 않는(임계값이 너무 높으면) 극단적 결과를 냈다. 차원이 너무 낮아 벡터가 희소해지는 문제였다.

**해결책**: 300차원 TF-IDF로 확장하고, 전체 2,826개 풀에서 변별력 있는 어휘를 독립적으로 선택함으로써 코사인 유사도 0.85가 실질적인 필터로 작동하게 만들었다.

## 5. 별점 기반 사기 패턴 분석

### 5.1 분석 방향성

별점을 별도 노드로 분리하는 방식(R-S-R 엣지)보다는, 별점 관련 분석 결과를 **유저 및 리뷰 노드의 파생 피처**로 녹여내는 방향으로 결정했다. 별점 자체는 이미 노드 피처로 포함되므로, 별점에서 파생되는 **고차원 정보**(이탈도, 엔트로피)를 추가하는 전략이다.

### 5.2 별점별 사기 비율 분석

**가설**: 1점 리뷰는 전체 수량은 적지만 사기 비율이 압도적으로 높을 것이다 (Pollute 전략).  
**5점 리뷰**는 수량이 많고 사기 비율도 높을 것이다 (Push 전략).

별점별 사기 비율을 실제로 계산하여 이 가설의 실증적 근거를 마련했다.

### 5.3 누적 평균 기반 Rating Deviation (핵심 피처)

**개념**: 개별 리뷰의 별점이 해당 식당의 "당시까지의 평균 별점"에서 얼마나 벗어났는가

**설계 시 주의한 점 — 데이터 누수 방지**:
- 단순히 전체 평균으로 이탈도를 계산하면, 미래 리뷰 정보가 현재 리뷰 계산에 포함되는 **시간 정보 누수**가 발생한다.
- 이를 방지하기 위해 **날짜순 정렬 후 누적 평균(Expanding Mean)**을 `shift(1)`로 처리하여, "현재 리뷰 작성 직전까지의 평균"만 참조하도록 했다.

**콜드 스타트 처리**:
- 식당의 첫 리뷰는 비교 기준이 없다.
- 이 경우 **Global Mean(전체 평균 평점)**을 베이지안 사전 확률로 대입하여 결측치를 처리했다.
- `is_cold_start` 지시 변수도 추가로 생성했다 (GNN 어텐션 메커니즘에서 활용 가능).

```
global_mean = df['rating'].mean()  # 약 3.xx 점
df['prod_cumulative_avg'] = df.groupby('prod_id')['rating']
    .transform(lambda x: x.expanding().mean().shift(1))
    .fillna(global_mean)
df['rating_deviation'] = (df['rating'] - df['prod_cumulative_avg']).abs()
```

**기대 효과**: 사기 리뷰(특히 1점 Pollute, 5점 Push)는 식당의 평균과 극단적으로 동떨어진 별점을 주는 경향이 있어 `rating_deviation` 값이 클 것으로 예상된다.

### 5.4 유저 행동 엔트로피 (Rating Entropy)

**개념**: 특정 유저가 얼마나 다양한 별점을 주는가  
- 사기 유저는 특정 별점(예: 항상 1점 또는 항상 5점)만 반복적으로 주는 경향이 있다 → **엔트로피가 낮다**
- 정상 유저는 경험에 따라 다양한 별점을 준다 → **엔트로피가 높다**

**정규화 처리**: 유저별 리뷰 수가 다르면 엔트로피의 스케일이 달라지므로, `엔트로피 / log(N)` 으로 정규화하여 리뷰 수 편향을 제거했다.

**결측치 처리**:
- 리뷰가 1개뿐인 유저는 엔트로피를 정의할 수 없다.
- `is_single_review` 지시 변수를 생성하고, 해당 유저의 엔트로피는 **중립값 0.5**로 대입했다.

### 5.5 삭제된 분석 항목: 별점-텍스트 모순 지수 (Dissonance)

초기 계획에서는 "별점은 5점인데 텍스트 감성은 부정적"인 모순을 탐지하는 `is_dissonant` 피처를 추가하려 했다. 그러나 분석 과정에서 **의미 있는 신호가 나오지 않아 삭제**했다.

이유: VADER/TextBlob 등 감성 분석 도구는 레스토랑 리뷰 도메인에서 정확도가 낮고, 사기 리뷰는 오히려 별점과 일치하는 짧은 감성 표현(예: "Excellent!" 5점)을 사용하는 경우도 많아 이 지표만으로는 구별이 어렵다는 판단이었다.
