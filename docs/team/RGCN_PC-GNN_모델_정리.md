# RGCN model & PC-GNN model

### 01 — 데이터 전처리

원본 데이터를 정리하고 필요한 데이터만 선별한다.

**핵심 작업 두 가지:**

**① 라벨 변환**
원본 데이터의 사기 표시가 `-1`로 되어 있어 `1`로 변환한다. (0=정상, 1=사기)

**② 밀도 중심 샘플링**
전체 60만 개를 그대로 사용하면 연산 비용이 과도하므로 5만 개를 선별한다. 단순 랜덤 샘플링은 그래프 연결성을 파괴하기 때문에 사용하지 않는다. GNN은 노드 간 연결이 충분해야 효과적으로 작동하기 때문이다.

샘플링 기준은 다음과 같다.

- 2013~2014년 데이터만 사용한다. (패턴이 일관된 시기)
- 리뷰가 많은 상위 200개 식당만 포함한다. (연결 밀도 확보)
- 사기 유저가 작성한 **모든** 리뷰를 포함한다. (위장 정상 리뷰까지 포착)
- 정상 유저는 리뷰 3개 이상 작성한 활성 유저만 포함한다. (연결성 확보)

최종 결과는 **50,950개**, 사기 비율 24.8%이다.

### 02 — 버스트 패턴 분석

"사기 리뷰어는 짧은 시간에 리뷰를 집중적으로 작성한다"는 가설을 검증한다.

주요 발견은 다음과 같다.

- 7일 안에 리뷰를 집중적으로 작성한 사기 유저가 전체의 18%에 달한다.
- 일부 유저는 7일 안에 모든 리뷰를 작성하였다. (집중도 100%)
- 2014년 12월에 **186명의 사기 유저가 동시에** 활동한 사실이 확인되었다. 이는 조직적 사기 캠페인이 실재함을 시사한다.

이 분석을 통해 다음 피처를 생성한다.

- `user_burst_max7d`: 7일 안에 최대 작성한 리뷰 수
- `user_burst_ratio`: 전체 리뷰 중 버스트 구간 비율

사기 유저 평균 **0.816** 대 정상 유저 평균 **0.065**로, 12.5배의 차이가 나타난다.

---

### 03-1 — 텍스트 단어 네트워크 분석

리뷰 텍스트에서 사기 리뷰와 정상 리뷰의 언어적 차이를 분석한다.

단어들을 PMI 기반 네트워크로 연결하여 각 집단에서 중심적으로 사용되는 단어를 도출하였다.

**사기 리뷰 특징 단어**: `manager`, `asked`, `told`, `said`, `minutes`
→ 주로 불만 상황을 묘사하는 패턴으로, 경쟁 식당을 공격하는 Pollute 전략에 해당한다.

**정상 리뷰 특징 단어**: `topped`, `sweetness`, `refreshing`, `bites`, `savory`
→ 음식의 맛과 질감을 구체적으로 묘사하는 패턴이다.

이 분석 결과를 활용하여 문장이 유사한 리뷰끼리 연결하는 R-TextSim-R 엣지를 생성한다.

---

### 03-2 — 별점 기반 분석

별점 부여 패턴을 통해 사기를 탐지한다.

사기 리뷰어의 주요 전략은 두 가지이다.

- **Pollute 전략**: 경쟁 식당에 1점을 대량 투하한다.
- **Push 전략**: 자신의 식당에 5점을 대량 투하한다.

이를 수치화한 피처는 다음과 같다.

- `rating_deviation`: 해당 식당 평균 별점과의 이탈 정도
- `norm_rating_entropy`: 유저가 부여하는 별점의 다양성 (낮을수록 편향된 패턴)

---

### 04 — GNN 모델 학습 및 비교

앞 단계에서 생성한 피처와 엣지를 기반으로 두 모델을 학습하고 성능을 비교한다.

**모델 1: RGCN (베이스라인)**

- 피처: 별점 1개
- 엣지: R-U-R 1종
- 특징: 이웃 노드를 구분 없이 균등 집계한다.

**모델 2: PC-GNN (메인 모델)**

- 피처: 버스트, 별점 이탈도, 엔트로피 등 7개
- 엣지: R-U-R, R-P-R, R-T-R 3종
- 특징: 어텐션 기반으로 신뢰할 수 있는 이웃만 선택적으로 집계하여 위장 정상 리뷰의 영향을 억제한다.

평가 지표는 **PR-AUC** (불균형 데이터에 적합)와 **Macro F1**이다.

---

## 모델 선택 근거

**목표**

본 프로젝트에서 사기 리뷰 탐지의 핵심 과제는 두 가지이다.

1. **카멜레온 문제 대응** — 사기 유저는 정상 리뷰를 끼워넣어 위장한다. 이 위장 리뷰에 의해 사기 신호가 희석되어서는 안 된다.
2. **클래스 불균형 대응** — 사기 리뷰 비율이 24.8%로, 단순 정확도는 실질적인 성능 지표로 적합하지 않다. PR-AUC와 Macro F1을 기준으로 평가한다.

모델 선택은 이 두 목표를 기준으로 결정하였다.

### RGCN — 베이스라인으로 선택한 이유

RGCN은 관계 타입별로 다른 가중치를 학습하는 가장 기본적인 멀티-릴레이션 GNN이다.

베이스라인으로 선택한 이유는 명확하다. **이 프로젝트의 핵심 설계인 멀티 릴레이션 엣지는 처리하되, 사기 탐지 특화 기능은 갖추지 않은 모델**이기 때문이다.

RGCN의 한계는 분명하다. 이웃 노드를 전부 균등 평균하여 집계하기 때문에, 사기 노드 주변에 위장 정상 리뷰가 섞여 있으면 사기 신호가 희석된다. 본 EDA에서 "사기 유저는 정상 리뷰도 함께 작성한다"고 확인한 바로 그 패턴에 취약한 구조이다.

RGCN은 **그래프 구조 자체의 기여**를 측정하는 기준점 역할을 한다. 메인 모델이 이를 상회해야 설계의 유효성을 주장할 수 있다.

### PC-GNN — 메인 모델로 선택한 이유

PC-GNN은 두 가지 메커니즘을 통해 작동한다.

- **Picker**: 학습 시 사기 노드를 전량 포함하고 정상 노드는 일부만 샘플링하여 클래스 불균형을 완화한다.
- **Chooser**: 이웃 노드를 전부 집계하지 않고, 유사도 기반 어텐션으로 신뢰할 수 있는 이웃만 선택적으로 집계한다.

이 두 기능이 본 프로젝트의 두 목표와 정확히 대응한다.

| 문제 | PC-GNN의 대응 |
| --- | --- |
| 위장 정상 리뷰 (카멜레온) | Chooser가 위장 이웃을 낮은 가중치로 억제한다. |
| 클래스 불균형 (24.8%) | Picker가 사기 노드 중심으로 학습 샘플을 구성한다. |

### 왜 다른 모델은 아닌가

**HIN 계열 (HAN, HGT 등)** 은 노드 타입이 여러 개일 때 강점을 발휘한다. 본 프로젝트는 리뷰 노드 하나에 모든 피처가 집중된 구조로, HIN의 이점을 활용하기 어렵다. 엣지 타입 3개는 RGCN과 PC-GNN이 이미 처리한다.

**CARE-GNN**은 카멜레온 문제는 다루지만 클래스 불균형 처리 메커니즘이 별도로 없다. PC-GNN이 두 문제를 동시에 다루며 YelpChi 벤치마크에서도 일관되게 높은 성능을 보이므로 PC-GNN을 선택하였다.

**GAGA, BWGNN** 등 최신 모델은 성능이 더 높을 수 있으나, 구현 복잡도 대비 본 프로젝트에서 추가로 얻는 이점이 불분명하다. 모델 복잡도보다 EDA에서 설계한 피처와 엣지의 효과를 검증하는 것이 본 프로젝트의 목적에 부합한다.

## 모델 설계 심화

### 결정 1: 유저 단위 train/test 분할

GNN은 노드를 학습할 때 이웃 노드의 정보를 메시지로 받아 자신을 표현한다. R-U-R 엣지는 같은 유저가 작성한 리뷰끼리 연결한다.

리뷰 단위로 분할하면 사기 유저 A의 리뷰 10개 중 8개는 train, 2개는 test에 배치될 수 있다. 이 경우 train의 8개 리뷰는 라벨(사기=1)이 알려진 상태에서 R-U-R로 test 리뷰 2개와 직접 연결된다. GNN 메시지 패싱 과정에서 사기 라벨 정보가 test 노드로 흘러가는 누수가 발생한다.

유저 단위 분할을 적용하면 동일 유저의 모든 리뷰가 같은 파티션에 배치된다. train-test 경계를 넘는 R-U-R 엣지가 존재하지 않으므로 라벨 누수가 원천적으로 차단된다.

---

### 결정 2: RGCN 피처를 `rating_norm` 1개로 제한한 이유

본 프로젝트에서 가장 중요한 설계 결정이다.

실험 결과는 다음과 같다.

| 모델 | 피처 | PR-AUC |
| --- | --- | --- |
| 로지스틱 회귀 (그래프 없음) | rating_norm 1개 | 0.28 |
| 로지스틱 회귀 (그래프 없음) | cold_start 포함 3개 | 0.76 |
| 로지스틱 회귀 (그래프 없음) | 전체 7개 | 0.81 |

`is_cold_start`, `is_single_review` 등의 피처가 그래프 구조 없이도 PR-AUC 0.76을 달성한다. 이 피처들의 변별력이 강해 모델이 그래프를 학습하지 않아도 대부분의 사기를 식별할 수 있게 된다.

RGCN에 7개 피처를 전부 제공하면 RGCN PR-AUC 0.87, PC-GNN PR-AUC 0.87로 두 모델의 성능이 동일하게 수렴한다. 이 경우 두 모델의 비교 자체가 의미를 잃는다.

해결책은 RGCN과 PC-GNN이 서로 다른 조건에서 비교되도록 설계하는 것이다.

- RGCN: 단순 피처(별점만), 단순 엣지(R-U-R만), 위장 이웃 대응 없음
- PC-GNN: EDA 기반 행동 피처 7개, 3종 엣지, Chooser 어텐션으로 위장 이웃 억제

이 설계에서 두 모델의 차이는 단순한 아키텍처 차이가 아니라, **EDA에서 발견한 사기 패턴을 얼마나 충실히 반영했는가**의 차이가 된다. Macro F1 0.51 대 0.86의 격차는 이 반영의 효과를 수치로 나타낸 것이다.

---

### 결정 3: 엣지를 모델별로 다르게 부여한 이유

**R-P-R을 RGCN에서 제외한 이유**

R-P-R은 같은 식당을 리뷰한 노드끼리 연결한다. 본 데이터는 상위 200개 식당에 리뷰가 집중되어 있고, 이 식당들 다수가 조직적 사기의 표적이다. 따라서 R-P-R 이웃끼리는 사기 비율이 구조적으로 높다.

RGCN은 이웃을 균등 평균하기 때문에, `rating_norm` 1개만으로도 R-P-R을 통해 "이 식당 이웃들의 사기 비율이 높으니 나도 사기"라는 신호가 강하게 전파된다. 실험에서 `rating_norm` + R-U-R + R-P-R만으로 RGCN PR-AUC 0.85 이상이 달성되었다. 이는 모델의 학습 능력이 아닌 데이터 구조에서 기인한 결과로, 성능의 원인을 명확히 구분하기 어렵게 만든다.

**R-T-R을 PC-GNN에만 부여한 이유**

R-T-R은 텍스트가 유사한 리뷰끼리 연결한다. 사기 리뷰끼리 문장 패턴이 유사해 사기-사기 간 엣지가 다수 생성되는 구조이다. 그러나 RGCN의 균등 집계는 사기 이웃과 정상 이웃을 구분 없이 합산하므로 이 엣지에서 신호보다 노이즈가 더 크게 발생한다.

PC-GNN의 Chooser는 릴레이션별로 어텐션 가중치를 학습한다. R-T-R에서 연결된 이웃 중 유사한 사기 노드에는 높은 가중치를, 우연히 연결된 정상 노드에는 낮은 가중치를 부여한다. 동일한 엣지라도 Chooser가 있어야 실질적인 신호로 활용될 수 있다.

---

### 결정 4: Picker ratio=3 + class-weighted loss를 병행한 이유

두 기법은 각각 다른 층위의 불균형 문제를 해결한다.

**Picker**는 배치 구성 단계에서 사기 노드를 전량 포함하고 정상 노드를 3배만 포함하여 배치 내 사기:정상 비율을 1:3으로 조정한다. 그러나 배치 비율을 균형 있게 맞추더라도 손실 함수가 일반 CrossEntropyLoss이면 정상 클래스가 75%인 실제 분포를 반영한 그래디언트가 발생한다. 배치에서는 균형을 잡았으나 손실 계산에서 다시 불균형이 재현되는 구조이다.

**class-weighted loss**는 손실 계산 단계에서 사기 노드의 오류에 더 큰 패널티를 부과한다. 사기를 정상으로 잘못 분류하는 경우에 더 높은 비용을 부과함으로써, 모델이 사기 탐지에 더 민감하게 반응하도록 유도한다.

ratio=3은 실험적으로 결정되었다. ratio=2이면 Picker의 과샘플링과 class weight가 중첩되어 정상 리뷰를 사기로 과분류하는 경향이 나타났다. ratio=4이면 정상 노드 비중이 커져 Picker의 효과가 감소하였다. ratio=3이 Fraud Recall과 Normal Precision 사이에서 가장 균형 잡힌 결과를 보였다.

---

## 최종적으로 두 모델이 보여주는 것

RGCN Macro F1 0.51에서 PC-GNN Macro F1 0.86으로의 격차는 단순히 모델 아키텍처 우열의 결과가 아니다.

RGCN은 별점 하나만으로 이웃을 전부 신뢰하여 집계하는 모델이다. PC-GNN은 EDA에서 발견한 버스트 패턴, 별점 이탈도, 엔트로피를 피처로 통합하고, 텍스트 유사도 기반 엣지를 추가하며, 위장 이웃을 어텐션으로 선별하는 모델이다.

이 격차는 **EDA에서 설계한 피처와 엣지가 실제 성능 향상으로 이어졌음을 실증하는 결과**이다.
