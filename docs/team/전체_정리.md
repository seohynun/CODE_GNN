    **2. 데이터 누수(Data Leakage) 이슈 - AUC 1.0000**
    • **발생한 문제 (Problem)**
    첫 번째 모델 학습에서 검증 AUC가 1.0000으로 나왔습니다. 분명히 비정상적인 결과였습니다.
    • **원인 분석 (Cause)**
    노드 피처로 사용한 user_fraud_ratio(해당 유저의 사기 리뷰 비율)와 prod_fraud_ratio(해당 식당의 사기 비율)를 테스트 노드를 포함한 전체 데이터셋의 label 컬럼을 기반으로 계산했습니다. 결과적으로 모델이 사기 비율 수치를 그대로 읽어 label을 예측하는 치트가 발생한 것입니다.
    • **적용한 해결 방법 (Solution)**
    user_fraud_ratio, prod_fraud_ratio 피처를 완전히 제거했습니다. label 정보가 필요 없는 통계(user_review_cnt, prod_review_cnt, rating_dev 등)로 대체하고, 라벨이 필요한 통계는 학습 데이터(idx_train)만을 기준으로 계산하도록 수정했습니다.
    **3. 그래프 과희소성 이슈 - AUC 0.55**
    • **발생한 문제 (Problem)**
    데이터 누수를 수정한 후 검증 AUC가 0.55까지 급락했습니다. 거의 무작위 예측 수준이었습니다.
    • **원인 분석 (Cause)**
    샘플링 전략 A(상위 식당 중심) + C(타임윈도우)로 추출한 서브그래프에서 대부분의 유저가 리뷰를 1개만 보유하고 있었습니다. 유저당 평균 리뷰 수가 1.7개에 불과해 R-U-R 엣지가 30,000 노드에 겨우 20,842개밖에 생성되지 않았습니다. GNN이 이웃 정보를 집계할 엣지 자체가 부족해 학습이 제대로 이루어지지 않은 것입니다.
    • **적용한 해결 방법 (Solution)**
    샘플링 전략을 사기 유저 중심으로 전면 재설계했습니다. 사기 리뷰를 1개 이상 작성한 유저의 모든 리뷰를 포함하고, 정상 활성 유저(리뷰 3개 이상) 리뷰를 1:4 비율로 결합했습니다. 또한 노드 수 상한을 30,000개에서 50,000개(규정 최대치)로 확장해 연결성을 보존했습니다. 그 결과 R-U-R 엣지가 20,842개에서 94,820개로 4.5배 증가했습니다.
    **4. 과적합(Overfitting) 이슈**
    • **발생한 문제 (Problem)**
    학습 손실(loss)은 꾸준히 감소하는데 검증 AUC가 0.73 부근에서 정체되거나 오히려 하락하는 현상이 발생했습니다.
    • **원인 분석 (Cause)**
    학습률(lr=0.01)이 너무 커서 초반에 빠르게 학습하다 검증 데이터에 과적합되었습니다. 또한 학습률 스케줄러가 없어 후반 학습이 수렴하지 못하는 문제도 있었습니다.
    • **적용한 해결 방법 (Solution)**
    학습률을 0.01에서 0.001로 낮추고, Dropout을 0.3에서 0.4로 강화했습니다. Weight decay를 5e-4에서 1e-3으로 높이고, CosineAnnealingLR 스케줄러를 추가해 학습 후반에 세밀하게 수렴하도록 했습니다. 검증 AUC 기준으로 최적 모델 체크포인트를 저장하는 방식도 도입했습니다.
    **5. 샘플링 후 노드 수 축소 시 연결성 파괴 이슈**
    • **발생한 문제 (Problem)**
    샘플링으로 50,000개를 확보했으나, 층화 샘플링으로 30,000개로 축소하면 유저당 평균 리뷰 수가 다시 1.6개로 떨어지는 현상이 반복됐습니다.
    • **원인 분석 (Cause)**
    축소 과정에서 같은 유저의 리뷰들이 흩어져 R-U-R 연결이 끊기는 구조적 문제였습니다. 아무리 좋은 샘플링 전략을 써도 이후에 무작위로 줄이면 연결성이 파괴됩니다.
    • **적용한 해결 방법 (Solution)**
    노드 수 제한을 포기하고 규정 최대치인 50,000개를 그대로 유지했습니다. 연결성 보존이 GNN 성능에 핵심임을 확인했습니다.
    **6. 임계값(Threshold) 조정 시도**
    • **발생한 문제 (Problem)**
    Macro F1 향상을 위해 사기 예측 임계값을 0.5에서 다양하게 조정해봤습니다.
    • **원인 분석 (Cause)**
    0.1부터 0.9까지 0.05 간격으로 탐색한 결과, 최적 임계값이 0.50으로 기존과 동일하게 나왔습니다. 개선폭 0.0000이었습니다.
    • **결론**
    이미 0.5가 최적이었으며 임계값 조정으로는 성능 개선이 불가능했습니다.
    **7. 텍스트 기반 EDA 및 파생 피처 발굴**
    • **발견한 인사이트**
    전체 60만 개 리뷰의 텍스트를 분석한 결과 다음과 같은 유의미한 차이를 발견했습니다.
    • 사기 리뷰 vs 정상 리뷰 비교:
    
        ◦ 평균 문장 수: 사기 6.9개 vs 정상 9.2개 (-2.3개)
        ◦ 숫자 포함 비율: 사기 32.1% vs 정상 43.4% (-11.3%)
        ◦ 구체적 메뉴 언급 비율: 사기 60.3% vs 정상 75.5% (-15.2%)
        ◦ 1점 별점에서의 사기 비율: 전체 평균 1:6.5인데 1점에서만 1:2.1로 사기가 3배 집중
    • **적용한 해결 방법 (Solution)**
    발굴한 인사이트를 바탕으로 4개의 파생 피처를 추가했습니다. 문장 수(정규화), 숫자 포함 여부, 구체적 메뉴 언급 여부, 문장당 단어 수(정규화). 이를 기존 구조적 피처 7개, BERT 임베딩 384차원과 합쳐 최종 395차원 노드 피처를 구성했습니다.
    **8. R-C-R 엣지 설계 개선**
    • **발생한 문제 (Problem)**
    처음 R-C-R(경쟁사 공격 관계) 엣지를 “같은 유저가 5점과 1점을 동시에 준 리뷰 연결”로 단순하게 설계했더니 엣지가 1,020개밖에 생성되지 않았습니다. 또한 정상 리뷰어도 맛있는 식당에 5점, 별로인 식당에 1점을 줄 수 있어 설계 근거가 약했습니다.
    • **원인 분석 (Cause)**
    극단 별점 동시 보유만으로는 경쟁사 공격 패턴을 특정하기 어려웠습니다. 추가적인 조건이 필요했습니다.
    • **적용한 해결 방법 (Solution)**
    세 가지 조건을 OR로 결합한 개선판을 적용했습니다.
    
        ◦ 조건1: 30일 이내 1점과 5점을 동시에 준 경우(자연스러운 소비자는 한 달 안에 극단 별점을 여러 개 잘 안 줌)
        ◦ 조건2: 같은 날 1점과 5점을 동시에 준 경우(하루에 도배하는 작업장 패턴)
        ◦ 조건3: 50자 이하 짧은 텍스트로 극단 별점을 준 경우(내용 없이 별점만 도배하는 패턴).
    

# 1. 프로젝트 개요

본 보고서는 YelpZip 데이터셋을 기반으로 그래프 신경망(GNN)을 활용하여 조직적 가짜 리뷰 네트워크(어뷰징 네트워크)를 탐지하는 모델의 전체 개발 과정과 결과를 기술합니다. 약 60만 개의 실제 Yelp 식당 리뷰에서 숨겨진 스팸 네트워크를 탐지하는 것이 목표입니다.

---

## 1.1 데이터셋 개요

YelpZip 데이터셋은 Yelp의 추천 및 필터링 시스템을 통해 수집된 608,458개의 식당 리뷰로 구성됩니다. 주요 컬럼은 다음과 같습니다.

- text: 리뷰 원본 텍스트 — NLP 임베딩 추출 및 사기 증거 시각화에 활용
- user_id: 리뷰 작성자 고유 식별자
- prod_id: 식당/상품 고유 식별자
- label: 타겟 변수 (원본: 사기=-1, 정상=1 → 변환 후: 사기=1, 정상=0)
- date: 리뷰 작성 날짜
- rating: 별점 (1~5점)
- tag: 추가 메타 태그

---

## 1.2 클래스 불균형

라벨 변환 후 데이터셋에서 심각한 클래스 불균형이 확인되었습니다. 정상 리뷰 528,019개(86.8%), 사기 리뷰 80,439개(13.2%)로 약 1:6.5의 불균형 비율을 보입니다. 이는 모델 학습 시 단순히 '모두 정상'으로 예측해도 86.8%의 정확도를 달성할 수 있어, 손실 함수에 pos_weight 가중치를 적용하여 사기 클래스에 더 큰 페널티를 부여하는 방식으로 대응하였습니다.

전체 데이터에서 별점별 사기 비율을 분석한 결과, 1점 리뷰에서 사기 비율이 압도적으로 높게 나타났습니다.

| 2점 | 6,242개 | 36,740개 | 14.5% | +1.3%p |

특히 1점 리뷰에서 사기 비율이 32.3%로 전체 평균(13.2%)의 약 2.5배에 달합니다. 이는 경쟁사 공격 목적의 1점 테러 리뷰가 다수 존재함을 시사하며, 커스텀 엣지 R-C-R(경쟁사 공격 관계) 설계의 핵심 근거가 되었습니다.

## 2.2 텍스트 문체 분석

사기 리뷰와 정상 리뷰의 텍스트 문체를 비교 분석한 결과, 다음과 같은 유의미한 차이가 확인되었습니다.

| **특징** | **사기 리뷰** | **정상 리뷰** | **차이** |
| --- | --- | --- | --- |
| 평균 텍스트 길이 | 474.2자 | 652.7자 | -178.5자 ↓ |
| 평균 문장 수 | 6.87개 | 9.22개 | -2.35개 ↓ |
| 숫자 포함 비율 | 32.1% | 43.4% | -11.3%p ↓ |
| 구체적 메뉴 언급 비율 | 60.3% | 75.5% | -15.2%p ↓ |
| 문장당 평균 단어 수 | 12.1개 | 12.7개 | -0.6개 ↓ |

분석 결과, 사기 리뷰는 정상 리뷰에 비해 짧고 문장 수가 적으며 숫자(구체적 경험 수치)와 메뉴명 언급이 현저히 낮습니다. 정상 리뷰어는 'pulled pork sandwich', 'french onion soup' 등 실제 섭취한 메뉴를 구체적으로 언급하는 반면, 사기 리뷰는 'great food', 'great service' 등 추상적 칭찬에 그치는 경향이 확인되었습니다. 이 4가지 특징(문장 수, 숫자 포함, 메뉴 언급, 문장당 단어 수)을 파생 피처로 추가하였습니다.

## 2.3 별점별 문체 분석

별점 구간별로 세분화한 분석에서 추가적인 인사이트를 도출하였습니다. 3~4점 구간에서 사기/정상 리뷰 간 차이가 가장 크게 나타났습니다(평균 문장 수 차이 약 3.3개, 숫자 포함 비율 차이 약 15~17%p). 이는 작업장이 중간 별점을 줄 유인이 없어 3~4점 사기 리뷰는 특히 짧고 내용이 빈약한 경향이 있기 때문으로 해석됩니다.

또한 1점 리뷰에서만 유일하게 사기 리뷰의 문장당 단어 수(14.3개)가 정상 리뷰(13.5개)보다 높게 나타났습니다. 이는 경쟁사 공격용 1점 리뷰가 설득력을 높이기 위해 의도적으로 상세하게 작성됨을 시사합니다.

# 3. 서브그래프 샘플링 및 데이터 분할

## 3.1 샘플링 전략

단순 무작위 추출은 노드 간 연결성을 파괴하여 GNN 학습을 불가능하게 하므로, 연결성을 보존하는 샘플링 전략을 설계하였습니다. 최종적으로 전략 A(상위 식당 중심)와 사기 유저 중심 샘플링을 결합하였습니다.

**샘플링 설계 근거 및 시행착오**

- 시도 1 (전략 A+C): 상위 300개 식당 + 2012~2014 타임윈도우 → 유저당 평균 리뷰7개로 R-U-R 엣지 극히 희소 (20,842개), GNN 학습 사실상 불가
- 시도 2 (전략 B): 활성 유저 중심 → 51만 개로 과다, 사기 비율 급락
- 시도 3 (매우 활성 유저): 리뷰 3개 이상 유저 + 상위 식당 → 축소 시 연결성 파괴 반복
- 최종 전략: 사기 리뷰 작성 유저의 전체 리뷰 + 정상 활성 유저(리뷰 3개 이상) 리뷰를 1:4 비율로 결합

**1:4 비율 설정 근거**

1. GNN 학습 관점: 사기 노드 주변 사기 이웃 밀도 확보로 패턴 학습 강화 
2. 평가 지표 관점: Macro F1은 소수 클래스에 민감하므로 훈련 데이터 내 사기 비율 적정 유지 필요
3. 샘플링 방법론 관점: 사기 데이터는 100% 실데이터, 정상 데이터만 일부 샘플링한 방식으로 데이터 조작이 아닌 표준 층화 샘플링에 해당
* pos_weight=4.47로 손실 함수에서 추가 보정하여 잔여 불균형 처리

# 4. 그래프 네트워크 설계

## 4.1 노드 설계

노드는 '리뷰(Review)' 단위로 고정하였으며, 총 395차원의 노드 피처를 구성하였습니다.

| **피처 그룹** | **차원** | **구성 요소** | **데이터 누수 여부** |
| --- | --- | --- | --- |
| 구조적 피처 | 7차원 | rating, text_len_log, is_extreme, month_norm, user_review_cnt, prod_review_cnt, rating_dev | 없음 (label 미사용) |
| BERT 임베딩 | 384차원 | all-MiniLM-L6-v2 (sentence-transformers) | 없음 |
| 텍스트 문체 피처 | 4차원 | 문장 수, 숫자 포함, 메뉴 언급, 문장당 단어 수 | 없음 |

**데이터 누수 방지 조치**

당초 설계한 user_fraud_ratio, prod_fraud_ratio 피처는 테스트 노드의 label 정보가 반영되어 AUC=1.0000의 비정상적 결과를 초래하였습니다. 해당 피처를 제거하고 label 정보가 불필요한 통계(리뷰 수, 별점 편차)로 대체하였으며, label 관련 통계는 학습 노드(idx_train) 기준으로만 계산하도록 수정하였습니다.

## 4.2 엣지 설계

기본 Relation 1개와 커스텀 Relation 4개를 설계하였습니다. 각 엣지의 설계 논리와 데이터 분석 근거는 다음과 같습니다.

**기본 Relation: R-U-R (Review-User-Review)**

동일 user_id를 공유하는 리뷰 쌍을 연결합니다. 작업장은 한 명의 유저가 여러 식당에 반복적으로 유사한 리뷰를 작성하는 패턴이 있으므로, 같은 유저의 리뷰를 연결하면 해당 네트워크가 그래프 구조에서 드러납니다. 유저당 최대 100개 페어로 제한하여 허브 노드의 과도한 연결 지배를 방지하였습니다.

- 최종 엣지 수: 86,930개

**커스텀 Relation 1: R-B-R (Review-Burst-Review)**

동일 식당(prod_id)에 60일 이내에 작성된 리뷰끼리 연결합니다. 별점 테러 및 홍보 작업장은 특정 식당을 대상으로 단기간에 집중적으로 리뷰를 게재하는 '버스트' 패턴을 보입니다. 60일 윈도우는 자연스러운 리뷰 빈도와 조직적 어뷰징의 경계를 구분하는 기준으로 설정하였습니다.

- 최종 엣지 수: 69,640개

**커스텀 Relation 2: R-S-R (Review-Star-Review)**

동일 식당에 동일 별점을 부여한 리뷰끼리 연결합니다. 조직적 가짜 리뷰는 특정 식당에 동일한 극단적 별점(1점 또는 5점)을 반복 부여하는 패턴이 있습니다. EDA에서 1점 사기 비율이 전체 평균의 2.5배임을 확인하였으며, 이를 그래프 구조로 인코딩합니다. 그룹당 최대 20개 페어로 제한하여 R-S-R이 다른 엣지를 압도하지 않도록 균형을 조정하였습니다.

- 최종 엣지 수: 50,332개

**커스텀 Relation 3: R-C-R (Review-Competitor-Review)**

동일 유저가 5점과 1점을 동시에 부여한 리뷰 쌍을 연결합니다. EDA에서 확인된 경쟁사 공격 패턴(A식당 5점 홍보 + B식당 1점 공격)을 포착하기 위해 설계하였습니다. 아래 세 조건 중 하나라도 충족 시 연결합니다.

- 조건 1: 30일 이내에 5점과 1점을 동시에 부여 (자연스러운 소비자는 단기간에 극단 별점을 반복하지 않음)
- 조건 2: 같은 날 5점과 1점을 동시에 부여 (하루 집중 도배 패턴)
- 조건 3: 50자 이하 짧은 텍스트로 극단 별점 부여 (내용 없이 별점만 도배하는 패턴)
- 최종 엣지 수: 222개

**커스텀 Relation 4: R-T-R (Review-Text-Review)**

BERT 임베딩 기반 코사인 유사도가 0.85 이상인 리뷰끼리 연결합니다. 동일 작업장에서 생산된 리뷰는 문체, 어휘, 문장 구조가 유사한 경향이 있습니다. 문체 분석에서 사기 리뷰가 'great food', 'great service' 등 특정 표현 패턴을 반복함을 확인하였으며, BERT 임베딩의 의미적 유사도를 통해 이를 포착합니다. 노드당 최대 10개 연결로 제한하여 노이즈 엣지를 억제하였습니다.

- 최종 엣지 수: 3,766개

| **엣지 유형** | **관계** | **엣지 수** | **탐지 대상 패턴** |
| --- | --- | --- | --- |
| R-U-R (기본) | 동일 유저 | 86,930개 | 같은 유저의 다수 식당 리뷰 도배 |
| R-B-R (커스텀) | 동일 식당 + 60일 이내 | 69,640개 | 특정 식당 단기 집중 공격 |
| R-S-R (커스텀) | 동일 식당 + 동일 별점 | 50,332개 | 동일 극단 별점 반복 부여 |
| R-C-R (커스텀) | 5점+1점 동시 보유 유저 | 222개 | 경쟁사 홍보+공격 동시 수행 |
| R-T-R (커스텀) | 텍스트 유사도 ≥ 0.85 | 3,766개 | 작업장 동일 템플릿 리뷰 |
| 전체 (중복 제거 + self-loop) | - | 260,478개 | - |

# 5. GNN 모델링

## 5.1 모델 선택 및 비교 실험

다양한 GNN 아키텍처를 실험하여 최적 모델을 선정하였습니다.

| **모델** | **PR-AUC** | **Macro F1** | **AUC-ROC** | **특징** |
| --- | --- | --- | --- | --- |
| FiveRelGNN v1 (SAGEConv) | 0.5543 | 0.7239 | 0.8585 | 기본 평균 집계 |
| FiveRelGNN v2 (2-hop) | 0.5275 | 0.7084 | 0.8469 | 2단계 이웃 집계 |
| CARE-GNN (최종) | 0.6718 | 0.7650 | 0.9016 | 유사도 기반 가중 집계 |

CARE-GNN이 모든 지표에서 압도적으로 우수한 성능을 보였습니다. 특히 PR-AUC에서 0.5543 → 0.6718로 +0.117의 큰 향상이 이루어졌습니다.

## 5.2 최종 모델: CARE-GNN 기반 FiveRelGNN

**CARE-GNN 선택 이유**

일반 SAGEConv는 이웃 노드를 단순 평균으로 집계하여 사기 관련 이웃과 무관한 이웃을 동등하게 처리합니다. CARE-GNN(Co-occurrence Attention-based Relation-aware Graph Neural Network)은 각 엣지마다 유사도 점수를 학습하여 사기 패턴과 관련된 이웃에 더 높은 가중치를 부여합니다. 이는 사기 탐지 태스크의 특성상 모든 이웃이 동등하게 중요하지 않다는 도메인 지식을 모델 구조에 반영한 것입니다.

**모델 구조**

| **레이어** | **구성** | **역할** |
| --- | --- | --- |
| Layer 1 (x5) | CAREConv(395 -> 128): R-U-R, R-B-R, R-S-R, R-C-R, R-T-R 각각 독립 처리 | 릴레이션별 유사도 기반 가중 집계 |
| 융합 | concat(5x128=640) -> BatchNorm -> ReLU -> Dropout(0.4) | 5가지 관계 정보 통합 |
| Layer 2 | GATConv(640 -> 128, heads=4) -> BatchNorm -> ReLU -> Dropout(0.4) | 중요 이웃에 attention 집중 |
| Layer 3 | SAGEConv(128 -> 128) -> BatchNorm -> ReLU -> Dropout(0.4) | 2-hop 이웃 정보 확장 |
| 분류기 | Linear(128->64) -> ReLU -> Dropout(0.4) -> Linear(64->2) | 최종 사기/정상 분류 |
| 총 파라미터 | 887,901개 | - |

## 5.3 학습 설정

| **하이퍼파라미터** | **값** | **설정 근거** |
| --- | --- | --- |
| Optimizer | Adam | 표준 선택 |
| Learning Rate | 0.001 | 과적합/미학습 균형 |
| Weight Decay | 0.001 | 과적합 방지 강화 |
| LR Scheduler | CosineAnnealingLR (T_max=200) | 학습 후반 세밀 수렴 |
| Epochs | 200 | 충분한 수렴 보장 |
| Dropout | 0.4 | 과적합 방지 |
| pos_weight | 4.47 | 클래스 불균형 보정 (정상 수 / 사기 수) |
| random_state | 42 | 재현성 확보 |

**pos_weight 적용 근거**

pos_weight = 정상 노드 수 / 사기 노드 수 = 4.47. 사기 리뷰를 정상으로 오분류 시 정상 오분류 대비 4.47배 더 큰 페널티를 부여합니다. 이를 통해 모델이 '모두 정상'으로 예측하는 퇴화 해를 방지하고, 사기 탐지에 집중하도록 유도합니다.

# 7. 주요 시행착오 및 해결 과정

## 7.1 데이터 누수 — AUC 1.0000 발생

첫 번째 모델 학습에서 검증 AUC 1.0000이 나타났습니다. 원인은 user_fraud_ratio, prod_fraud_ratio 피처를 테스트 노드 포함 전체 데이터셋의 label 기준으로 계산한 것으로, 모델이 사기 비율 수치를 그대로 읽어 정답을 도출하는 치트가 발생하였습니다. 해당 피처를 제거하고 label 불필요 통계로 대체하여 해결하였습니다.

## 7.2 그래프 과희소성 — AUC 0.55 급락

데이터 누수 수정 후 AUC가 0.55까지 하락하였습니다. 원인은 샘플링 전략 A+C로 추출 시 대부분 유저가 리뷰 1개만 보유하여 R-U-R 엣지가 20,842개에 불과했습니다. 샘플링 전략을 사기 유저 중심으로 전면 재설계하여 R-U-R 엣지를 94,820개로 확대하고 성능을 회복하였습니다.

## 7.3 엣지 수 불균형 — R-S-R 과도한 연결

R-S-R 엣지가 206,712개로 과도하게 생성되어 다른 엣지 신호를 압도하는 문제가 발생하였습니다. RSR_MAX_PER_GROUP을 50에서 20으로 조정하여 50,332개로 제한하고 엣지 간 균형을 회복하였습니다.

## 7.4 모델 과대화 시도 — 성능 역효과

hidden 차원을 128에서 256으로 확장하고 FocalLoss를 적용하는 실험에서 파라미터가 250만 개로 증가하였으나 Macro F1이 0.66으로 오히려 하락하였습니다. 50,000개 데이터에서 과대 모델은 과적합이 심화됨을 확인하고, hidden=128로 원복하였습니다.

# 8. 결론

본 프로젝트는 YelpZip 데이터셋에서 CARE-GNN 기반 FiveRelGNN 모델을 구축하여 AUC-ROC 0.9016, PR-AUC 0.6718, Macro F1 0.7650을 달성하였습니다. 핵심 기여는 다음과 같습니다.

- EDA 기반 엣지 설계: 별점별 사기 비율 분석, 텍스트 문체 분석을 통해 데이터 근거가 있는 5가지 관계(R-U-R, R-B-R, R-S-R, R-C-R, R-T-R)를 설계하였습니다.
- BERT 임베딩 활용: sentence-transformers의 all-MiniLM-L6-v2 모델로 384차원 텍스트 임베딩을 추출하여 노드 피처의 의미적 표현력을 강화하였습니다.
- CARE-GNN 적용: 단순 평균 집계를 넘어 유사도 기반 가중 집계를 통해 사기 탐지에 핵심적인 이웃 노드에 집중하는 학습이 가능하였습니다.
- 데이터 누수 방지: label 기반 피처를 train 노드 기준으로만 계산하여 평가의 신뢰성을 확보하였습니다.
